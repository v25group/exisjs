# Middleware (`exisjs/middleware`)

ExisJS ships with an optimized suite of core middleware. Rather than relying on heavy external dependencies, ExisJS implements security and utility middleware directly.

All middlewares can be applied globally in `server.ts`, folder-wide in `boundary.ts`, or locally on specific controllers/routes.

---

## How to Apply Middleware

ExisJS provides first-class support for both Object-Oriented and Functional middleware application.

**Class-Based (OOP)**
```typescript filename="src/http/users/route.ts"
import { Controller, Get, Use } from 'exisjs/decorators'
import { ipFilter } from 'exisjs/middleware'

@Controller('/users')
@Use(ipFilter({ allow: ['192.168.1.0/24'] })) // Applies to entire controller
export default class UserController {
  @Get('/stats')
  getStats() {
    return { users: 100 }
  }
}
```

**Functional**
```typescript filename="src/http/users/route.ts"
import { controller, route } from 'exisjs/router'
import { ipFilter } from 'exisjs/middleware'

export default controller({
  middleware: [ipFilter({ allow: ['192.168.1.0/24'] })],

  getStats: route.get('/stats', {
    async handle() {
      return { users: 100 }
    }
  })
})
```

## Security Middleware

### `helmet(options?)`
Sets 14+ strict security headers (HSTS, CSP, XSS Protection, No Sniff, Frameguard) to protect your application.

```typescript
import { helmet } from 'exisjs/middleware'

app.use(helmet())
```

### `csrf(options)`
Implements the Signed Double Submit Cookie pattern for Cross-Site Request Forgery (CSRF) protection.

### `timeout(options?)`
Automatically times out requests that exceed the specified duration, returning a `503 Service Unavailable` response (or custom status code).

- **Default**: `60000` (60 seconds)
- **Options**:
  - `ms` (`number`): Timeout duration in milliseconds.
  - `statusCode` (`number`): Status code to respond with (default: `503`).
  - `message` (`string`): Error message returned to the client.
  - `exclude` (`(string | RegExp)[]`): Array of route paths or regex patterns to exempt from timeout checks.

```typescript
import { timeout } from 'exisjs/middleware'

app.use(timeout({
  ms: 60000,
  exclude: ['/webhooks/*', '/ai/stream'],
}))
```

Handlers can dynamically alter the active timeout using `req.setTimeout(ms)` or `req.clearTimeout()`.

### `fileUpload(options?)`
First-party multipart form data parsing and file upload middleware.

- **Methods**:
  - `fileUpload.single(fieldName, options?)`: Parses a single file into `req.file`.
  - `fileUpload.array(fieldName, maxCount?, options?)`: Parses multiple files with the same field into `req.files` (`UploadedFile[]`).
  - `fileUpload.fields([{ name, maxCount }])`: Parses multiple distinct fields into `req.files` (`Record<string, UploadedFile[]>`).
  - `fileUpload.any(options?)`: Accepts any uploaded files.
  - `fileUpload.none(options?)`: Accepts only text fields; rejects file uploads.
- **Options**:
  - `dest` (`string`): Directory path to save uploaded files to disk automatically.
  - `maxBytes` (`number`): Maximum file size in bytes (shorthand for `limits.fileSize`).
  - `mimeTypes` (`string[]`): Array of permitted MIME types (e.g. `['image/png', 'image/jpeg']`).
  - `limits` (`{ fileSize?: number; files?: number }`): Detailed size and count limits.

```typescript
import { fileUpload } from 'exisjs/middleware'

app.post('/avatar', fileUpload.single('avatar', {
  maxBytes: 5 * 1024 * 1024,
  mimeTypes: ['image/*'],
}), (req, res) => {
  const file = req.file // UploadedFile { filename, originalname, mimetype, size, buffer }
  res.json({ success: true, filename: file.filename })
})
```

### `fromExpress(middleware)`
Seamlessly adapts standard Express/Connect middleware (such as `multer`) to run within the ExisJS pipeline.

```typescript
import { fromExpress } from 'exisjs/middleware'
import multer from 'multer'

const upload = multer({ dest: './uploads' })

app.post('/upload', fromExpress(upload.single('file')), (req, res) => {
  res.json({ file: (req.raw as any).file })
})
```

### `hpp()`
HTTP Parameter Pollution protection.

### `dbSanitize(options?)`
Sanitizes query and body payloads from NoSQL injection attempts.

## Traffic & Reliability Middleware

### `rateLimit(options?)`
High-performance rate limiter running in-memory and off-heap via Rust native bindings (`NativeRateLimiter`).

> [!NOTE]
> Core rate limiting is scoped to in-memory native execution. Distributed multi-instance Redis rate limiting moves to `@exisjs/cache`.

```typescript
import { rateLimit } from 'exisjs/middleware'

app.use(rateLimit({
  windowMs: 60000,
  max: 100
}))
```

### `timeout(options?)`
Terminates long-running requests that exceed the specified threshold, responding with `503 Service Unavailable` (or custom status). Defaults to 60,000ms.

```typescript
import { timeout } from 'exisjs/middleware'

app.use(timeout({
  ms: 60000,
  statusCode: 504,
  message: 'Gateway Timeout',
  exclude: ['/webhooks/*', '/ai/stream'],
}))
```

### `routeTimeout(msOrOptions)`
Applies an endpoint-specific timeout. If a global timeout is already active, dynamically overrides the timer for this route. If no global timeout exists, initializes an isolated timeout timer. Passing `0` disables timeouts for streaming/exports.

```typescript
import { routeTimeout } from 'exisjs/middleware'

app.post('/heavy-task', routeTimeout(120000), (req, res) => { ... })
```

### `idempotent(options?)`
Caches responses based on the `Idempotency-Key` header into off-heap native memory to prevent duplicate mutations.

```typescript
import { idempotent } from 'exisjs/middleware'

export const handlePayment = [
  idempotent({ ttlMs: 86400000 }),
  async (req, res) => { ... }
]
```

### `dedupe(options?)`
Prevents duplicate identical in-flight requests from being computed simultaneously.

### `backpressure(options?)`
Monitors the Node.js Event Loop delay in real-time, shedding load when overloaded.

### `ipFilter(options)`
Fast CIDR-based IP whitelist/blacklist filter.

## Utility Middleware

### `cors(options?)`
Cross-Origin Resource Sharing handler supporting preflight, dynamic origin matching, and credential headers.

### `requestId()`
Injects a unique `X-Request-Id` into every incoming request and outgoing response header.

### `requestLogger(options?)`
High-performance request logger powered by Pino.

### `serveStatic(root, options?)`
Static file server supporting streaming and caching headers.
