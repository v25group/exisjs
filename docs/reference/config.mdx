# `exisjs/config`

The `exisjs/config` module exposes configuration types, Phase constants, the `defineConfig()` helper, and environment-loading utilities used by `exis.config.ts` and runtime server initializers.

## `defineConfig(config)`

A type-helper function that returns the passed `ExisConfig` object without modifications, providing TypeScript autocompletion and validation in IDEs.

```typescript
function defineConfig(config: ExisConfig): ExisConfig
```

### Static Configuration Example

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default defineConfig({
  port: 4000,
  host: '0.0.0.0',
  cors: {
    origin: ['https://example.com', 'https://admin.example.com'],
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'DELETE', 'PATCH', 'OPTIONS'],
  },
  helmet: {
    enabled: true,
    contentSecurityPolicy: true,
    xFrameOptions: 'SAMEORIGIN',
  },
  logger: {
    level: 'info',
    pretty: false,
    redact: ['req.headers.authorization', 'req.headers.cookie'],
  },
  cluster: {
    workers: 'safe',
  },
  telemetry: {
    enabled: true,
    serviceName: 'order-service',
    exporter: 'otlp',
  },
  healthcheck: {
    enabled: true,
    path: '/healthz',
  },
  docs: {
    enabled: true,
    path: '/api/docs',
    title: 'Order Service API',
    version: '1.0.0',
  },
})
```

## Dynamic Phase-Based Configuration

You can export an asynchronous function from `exis.config.ts`. ExisJS passes the active phase string as the first argument, allowing you to alter settings depending on whether the application is running in development, building for production, running in production, or executing tests.

```typescript filename="exis.config.ts"
import {
  defineConfig,
  PHASE_DEVELOPMENT_SERVER,
  PHASE_PRODUCTION_BUILD,
  PHASE_PRODUCTION_SERVER,
  PHASE_TEST,
} from 'exisjs/config'

export default async function (phase: string, { defaultConfig }: { defaultConfig: any }) {
  const isDev = phase === PHASE_DEVELOPMENT_SERVER
  const isTest = phase === PHASE_TEST

  return defineConfig({
    port: isTest ? 0 : Number(process.env.PORT) || 4000,
    host: '0.0.0.0',

    // Spawn 1 worker in dev, safe CPU count in production
    cluster: {
      workers: isDev || isTest ? 1 : 'safe',
    },

    // Permissive CORS in local development, strict origins in production
    cors: {
      origin: isDev ? '*' : ['https://app.example.com'],
      credentials: true,
    },

    // Human-readable logs in development, JSON structured logs in production
    logger: isDev
      ? { level: 'debug', pretty: true }
      : isTest
        ? false
        : { level: 'info', pretty: false },

    // Enable API documentation in development only
    docs: {
      enabled: isDev,
      path: '/docs',
    },
  })
}
```

### Phase Constants

| Constant | Value | Triggered When |
| :--- | :--- | :--- |
| `PHASE_DEVELOPMENT_SERVER` | `'phase-development-server'` | Executing `npx exisjs dev` |
| `PHASE_PRODUCTION_BUILD` | `'phase-production-build'` | Executing `npx exisjs build` |
| `PHASE_PRODUCTION_SERVER` | `'phase-production-server'` | Executing `npx exisjs start` |
| `PHASE_TEST` | `'phase-test'` | Executing `npx exisjs test` |

## `ExisConfig` Interface Reference

The root configuration schema accepted by `exis.config.ts`:

### Network & Core Server Options

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `port` | `number` | `4000` | Port for the HTTP server to listen on. Can be overridden via CLI `-p`. |
| `host` | `string` | `'0.0.0.0'` | Network interface binding. |
| `server` | `'auto' \| 'node' \| 'bun' \| 'uws'` | `'auto'` | HTTP server backend. Automatically selects Bun or Node when detected. |
| `cluster` | `{ workers?: number \| 'auto' \| 'safe' \| 'max' }` | `{ workers: 1 }` | Multi-process worker clustering. `'safe'` uses available CPU cores minus 1; `'max'` uses all available cores. |
| `trustProxy` | `boolean \| number` | `false` | Enables reverse-proxy IP headers (`X-Forwarded-For`, `CF-Connecting-IP`, `True-Client-IP`). |
| `bodyLimit` | `number` | `10485760` (10MB) | Maximum payload size in bytes for JSON and URL-encoded request bodies. |
| `compression` | `boolean` | `false` | Enables gzip and Brotli response compression. |
| `etag` | `boolean` | `false` | Enables ETag computation for dynamic responses. |
| `debugRouting` | `boolean` | `false` | Logs the matched file-system route file and applied boundaries for every request. |
| `asyncContext` | `boolean` | `false` | Enables `AsyncLocalStorage` context tracking (`getContext()`). |
| `transformResponse` | `boolean \| ((data: any, req: any, res: any) => any)` | `false` | Global transformation function to wrap route responses in a standardized envelope. |

### Security & Middlewares

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `cors` | `boolean \| CorsConfig` | `{ origin: '*', methods: ['GET', 'POST', ...] }` | Cross-Origin Resource Sharing settings. Set to `false` to disable. |
| `helmet` | `boolean \| HelmetConfig` | `{ enabled: true }` | Strict security response headers (CSP, X-Frame-Options, X-Content-Type-Options). |
| `logger` | `boolean \| LoggerConfig` | `false` | Pino structured logger configuration with automatic credential redaction. |
| `blockSuspiciousProbes` | `boolean \| BlockProbesOptions` | `false` | Automatically drops requests targeting known exploit paths (`.env`, `.git`, `wp-admin`). |
| `keepAlive` | `boolean \| KeepAliveConfig` | `false` | HTTP keep-alive timeout and connection socket limits. |

### Observability & Diagnostics

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `telemetry` | `boolean \| TelemetryConfig` | `{ enabled: false, exporter: 'console' }` | OpenTelemetry tracing and span reporting (`'otlp'` or `'console'`). |
| `metrics` | `boolean \| MetricsConfig` | `{ enabled: false, path: '/metrics' }` | Prometheus-compatible metrics endpoint. |
| `healthcheck` | `boolean \| HealthCheckConfig` | `{ enabled: false, path: '/_health' }` | Liveness and readiness health probe route. |
| `docs` | `boolean \| SwaggerConfig` | `{ enabled: false, path: '/docs' }` | Interactive OpenAPI / Swagger UI documentation generation. |

### Development & File Watching

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `watch` | `WatchConfig` | `{ debounceMs: 250 }` | File watching paths, patterns, and debounce timings. |
| `dev` | `DevConfig` | `{ usePolling: true }` | Development server settings, including chokidar polling interval for Windows environments. |
| `plugins` | `ExisPlugin[]` | `[]` | Array of framework plugins to initialize during application bootstrap. |
| `test` | `TestConfig` | `{ include: ['tests/**/*.test.ts'] }` | Test file matching patterns and setup file scripts. |

## Environment Utility Functions

The `exisjs/config` module also exports low-level environment-loading helpers used internally by the CLI:

### `loadEnv(cwd?, mode?, override?)`

Loads cascading `.env` files from `cwd` based on the specified execution mode (`development`, `production`, `test`).

```typescript
import { loadEnv } from 'exisjs/config'

const envMap = loadEnv(process.cwd(), 'production')
```

### `parseEnv(source)`

Parses raw `.env` string contents into a key-value record without mutating `process.env`.

```typescript
import { parseEnv } from 'exisjs/config'

const parsed = parseEnv(`
PORT=5000
DATABASE_URL=postgres://user:pass@localhost:5432/db
`)
```
