# Dependency Injection (`exisjs/di`)

ExisJS ships with a powerful, built-in Inversion of Control (IoC) Container. 

It fully supports standard Class-Based constructor injection (similar to NestJS or Angular) but also introduces a highly optimized `inject()` function that allows perfectly typed, deeply nested dependency injection inside purely functional architectures.

---

## Providing Dependencies

Before a dependency can be injected, it must be provided to the application container. This is typically done in your plugins or the global `server.ts` file using `app.provide()`.

### Provider Types

ExisJS supports four types of providers:

**1. Value Providers**
Provide static, pre-instantiated values or configuration objects.
```typescript
app.provide('API_KEY', { useValue: 'sk_live_123' })
```

**2. Class Providers**
Provide a class constructor. ExisJS will automatically instantiate it the first time it is resolved.
```typescript
app.provide('UserService', { useClass: UserService })
```

**3. Factory Providers**
Provide a synchronous or asynchronous function to generate the value dynamically.
```typescript
app.provide('Database', { 
  useFactory: async () => {
    const db = new DatabaseConnection()
    await db.connect()
    return db
  }
})
```

**4. Direct Injection**
If you pass an undecorated Class or object directly, ExisJS will attempt to resolve it automatically.
```typescript
app.provide(AuthService, AuthService)
```

---

## Scopes (`singleton`, `request`, `transient`)

By default, all providers in ExisJS are **Singletons**. They are instantiated once and cached for the lifetime of the application.

ExisJS supports three provider scopes in the `@Injectable()` decorator and `app.provide()`:

- **`singleton` (Default)**: Instantiated once and cached for the lifetime of the application.
- **`request`**: A new instance is created exclusively for each incoming HTTP request, and garbage collected afterward.
- **`transient`**: A new instance is created every single time the dependency is injected or resolved.

```typescript
app.provide('TraceLogger', { 
  useClass: RequestScopedLogger, 
  scope: 'request' 
})

app.provide('OperationContext', {
  useClass: OperationContext,
  scope: 'transient'
})
```

> [!WARNING]
> Request-scoped providers can severely impact application performance because they force the engine to allocate new memory and construct new classes on every single HTTP request. Only use `request` scope when strictly necessary.

## Injecting Dependencies

### 1. Functional Injection (`inject()`)

The true superpower of ExisJS is the `inject()` hook. 

Powered by Node.js `AsyncLocalStorage`, `inject()` can be called from **anywhere** within a request lifecycle (Controllers, Middlewares, nested utility functions) without needing to explicitly pass the `app` or `req` objects down the call chain!

```typescript filename="src/http/users/route.ts"
import { route, controller } from 'exisjs/router'
import { inject } from 'exisjs/di'
import { Database } from '../db' // The class definition

export default controller({
  getUsers: route.get('/', {
    async handle() {
      // Automatically resolves the correct instance from the global container!
      // Type is automatically inferred as `Database`.
      const db = inject(Database) 
      
      const apiKey = inject<string>('API_KEY')
      
      return db.query('SELECT * FROM users')
    }
  })
})
```

> [!NOTE]
> `inject()` relies on the active execution context. If you call `inject()` outside of an active HTTP request or application lifecycle hook (e.g., in a background `setInterval` without context), it will throw an error.

### 2. Constructor & Property Injection in Classes (OOP)

ExisJS supports full OOP constructor parameter and property field injection with **automatic parameter type reflection**:
- **Automatic Type Reflection**: If `emitDecoratorMetadata: true` is enabled in `tsconfig.json`, ExisJS inspects `design:paramtypes` and automatically maps constructor parameter classes directly to dependencies registered in `INJECTABLE_REGISTRY`. You do not need `@Inject()` on standard service classes!
- **Property-Level `@Inject()`**: Inject dependencies directly onto class properties (`@Inject(Token) public service!: Service`) with automatic `design:type` reflection fallback.
- **Token Injection (`@Inject(token)`)**: Use `@Inject('TOKEN')` when injecting custom strings, config objects, or symbols.
- **Optional Dependencies (`@Optional()`)**: Mark dependencies that can safely resolve to `undefined` if not registered.
- **Forward References (`forwardRef(() => Service)`)**: Resolve circular dependencies between services using lazy forward references and ES6 Proxy delegates.

```typescript filename="src/http/users/route.ts"
import { Controller, Get, Param } from 'exisjs/decorators'
import { Inject, Optional, forwardRef } from 'exisjs/di'
import { UserService } from './service'
import { ConfigService } from '../config/service'

@Controller('/users')
export default class UserController {
  // 1. Property-level injection
  @Inject(ConfigService)
  private config!: ConfigService

  // 2. Optional property injection
  @Inject('ANALYTICS')
  @Optional()
  private analytics?: any

  constructor(
    // 3. Automatically resolved from INJECTABLE_REGISTRY via type reflection!
    private userService: UserService,
    // 4. Explicit token injection
    @Inject('DATABASE_URL') private dbUrl: string,
    // 5. Circular dependency resolution via forwardRef
    @Inject(forwardRef(() => UserService)) private circularRef: UserService
  ) {}

  @Get('/:id')
  async getUser(@Param('id') id: string) {
    return this.userService.findById(id)
  }
}
```

## Lifecycle Hooks (`OnInit`, `OnDestroy`)

Providers can implement lifecycle interfaces. When the application container initializes or gracefully closes, ExisJS automatically triggers these hooks:

- **`OnInit` (`onInit()` / `onModuleInit()`)**: Executed when the container initializes during `app.create()` or `app.listen()`.
- **`OnDestroy` (`onDestroy()` / `onModuleDestroy()`)**: Executed when the application receives a termination signal or `app.close()` is called.
- **`OnApplicationBootstrap` (`onApplicationBootstrap()`)**: Executed after all modules are initialized and before the server begins listening for incoming requests.

```typescript filename="src/http/database/service.ts"
import { Injectable, type OnInit, type OnDestroy } from 'exisjs/decorators'

@Injectable()
export class DatabaseService implements OnInit, OnDestroy {
  async onInit(): Promise<void> {
    await this.pool.connect()
  }

  async onDestroy(): Promise<void> {
    await this.pool.end()
  }
}
```
