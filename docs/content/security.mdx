# Security & Edge Middleware

ExisJS provides native, zero-dependency edge and request security middleware built directly into core.

---

## 1. Edge Security Middlewares

The following security middlewares are available from `exisjs/middleware` and can be registered globally in `server.ts` or scoped to route trees via `boundary.ts`:

- `helmet(options?)`: Sets 14+ secure HTTP headers (Strict-Transport-Security, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, and CSP).
- `csrf(options)`: Enforces the Signed Double Submit Cookie pattern to protect state-changing requests (POST, PUT, DELETE) from CSRF attacks.
- `hpp()`: Protects against HTTP Parameter Pollution attacks by ensuring array query parameters/form fields are safely handled.
- `mongoSanitize()`: Strips MongoDB operator keys (keys starting with `$` or containing `.`) from `req.body`, `req.query`, and `req.params`.
- `dbSanitize(options?)`: Protects against NoSQL query operator injection (`$where` and other malicious keys) before reaching database layers.
- `timeout(ms)`: Automatically terminates requests that exceed the specified timeout limit, returning a 503 response.

> [!TIP]
> Security middlewares like `hpp()`, `mongoSanitize()`, and `dbSanitize()` automatically synchronize with the request body parser. If registered globally before route handlers, they safely await the body and sanitize it deterministically without runtime crashes.

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { helmet, csrf, timeout, hpp, mongoSanitize } from 'exisjs/middleware'

export default exis({
  async onStart(app) {
    app.use(helmet())
    app.use(timeout(10000))
    app.use(hpp())
    app.use(mongoSanitize())
  },
})
```

## 2. In-Memory Rate Limiting

The core `rateLimit` middleware provides high-performance in-memory and off-heap native rate limiting with standard HTTP response headers:

```typescript filename="src/http/boundary.ts"
import { defineBoundary } from 'exisjs/router'
import { rateLimit } from 'exisjs/middleware'

export const config = defineBoundary({})

// Apply rate limiting chain step across the boundary
export const limiter = rateLimit({
  windowMs: 60 * 1000, // 1 minute window
  max: 100, // 100 requests per window
  message: 'Too many requests from this IP, please try again after a minute',
  keyGenerator: (req) => req.ip, // Uses normalized IPv4/IPv6 client IP
})
```

### Standard Rate Limit Headers

`rateLimit` automatically emits standard IETF draft and legacy rate-limiting headers on every response:

| Header                | Description                                                                | Example                 |
| :-------------------- | :------------------------------------------------------------------------- | :---------------------- |
| `RateLimit-Limit`     | Maximum request quota for the configured window.                           | `100`                   |
| `RateLimit-Remaining` | Remaining requests permitted within the current window.                    | `42`                    |
| `RateLimit-Reset`     | Time remaining in seconds until the window quota resets.                   | `18`                    |
| `Retry-After`         | Included on `429 Too Many Requests` (RFC 6585) indicating seconds to wait. | `18`                    |
| `X-RateLimit-*`       | Legacy header equivalents for backwards compatibility.                     | `X-RateLimit-Reset: 18` |

> [!NOTE]
> The core `rateLimit` middleware runs using an in-memory native off-heap store. For distributed, multi-instance rate limiting backed by Redis, use `@exisjs/cache`.

## 4. Timing-Safe Operations & Authentication

To prevent side-channel timing attacks when validating authentication tokens, API keys, HMAC signatures, or webhook secrets, ExisJS provides the `timingSafeEqual` helper:

```typescript filename="src/http/common/guards/auth.guard.ts"
import { timingSafeEqual } from 'exisjs/middleware'
import { UnauthorizedException } from 'exisjs/error'

export function apiKeyGuard(req: any) {
  const apiKey = req.headers['x-api-key']
  const secretKey = process.env.API_KEY

  if (!timingSafeEqual(apiKey, secretKey)) {
    throw new UnauthorizedException('Invalid API Key')
  }
}
```

`timingSafeEqual` executes in constant time regardless of string lengths or partial matching prefixes, neutralizing timing analysis exploits.

## 5. Security Scanner Noise Suppression & Blackhole Handler

ExisJS includes built-in protection against automated vulnerability bots scanning for `.env`, `/.git`, `/.DS_Store`, WordPress/PHP configs, and Java actuator dumps:

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { blockSuspiciousProbes } from 'exisjs/middleware'

export default exis({
  async onStart(app) {
    // Intercepts scanner probes and blackholes them without triggering downstream error logs
    app.use(
      blockSuspiciousProbes({
        blackhole: true, // Terminate immediately with 404/empty body
        silent: true, // Suppress 404 noise from production logs
      })
    )
  },
})
```
