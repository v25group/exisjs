# Gateways (Middleware & Modules)

Gateways act as a configuration entry point for specific folders in your file-system routing architecture.

Instead of writing programmatic middleware declarations like `app.use('/admin', requireAuth)`, you can place a `gateway.ts` file inside a folder to scope **Middleware**, **CORS**, and **Dependency Injection** to that specific domain.

## Cascading Middleware

The most common use-case for a gateway is applying middleware arrays to a group of routes.

### Functional Paradigm

```typescript className="language-typescript" filename="src/http/admin/gateway.ts"
import { defineGateway } from 'exisjs/router'
import { requireAuth } from '../../middleware/auth'
import { cors, helmet } from 'exisjs/middleware'

export default defineGateway({
  // This middleware array runs before ANY route in /admin/*
  middleware: [
    helmet(),
    compress(),
    cache({ ttlMs: 60000 }),
    requireAuth
  ],
  
  // Enforce strict CORS for this folder
  cors: {
    origin: 'https://admin.yourdomain.com',
    methods: ['GET', 'POST', 'DELETE']
  },

  // Append custom default headers to all responses
  headers: {
    'X-Admin-Api-Version': '2.0'
  }
})
```

### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/admin/gateway.ts"
import { Gateway } from 'exisjs/decorators'
import { requireAuth } from '../../middleware/auth'
import { helmet } from 'exisjs/middleware'

@Gateway({
  // This middleware array runs before ANY route in /admin/*
  middleware: [
    helmet(),
    compress(),
    cache({ ttlMs: 60000 }),
    requireAuth
  ],
  
  // Enforce strict CORS for this folder
  cors: {
    origin: 'https://admin.yourdomain.com',
    methods: ['GET', 'POST', 'DELETE']
  },

  // Append custom default headers to all responses
  headers: {
    'X-Admin-Api-Version': '2.0'
  }
})
export default class AdminGateway {}
```

When a request comes in for `/admin/users`, ExisJS processes the Gateway's middleware sequentially before it ever reaches your `route.ts` file.

## Folder-Scoped CORS

Handling CORS across an API can require granular control. For instance, you might want your `/public` folder to accept requests from anywhere, while restricting your `/billing` folder to a strict frontend domain. ExisJS allows you to define the `cors` property in your Gateway, overriding the global configuration for that specific folder.

## File-Based Modules (Domain-Driven Design)

In addition to serving as an interceptor for middleware, `gateway.ts` acts as a module boundary, enabling **Domain-Driven Design (DDD)** via the file system.

### Providers (Dependency Injection)

If you have a database service unique to your `/users` domain, encapsulate it strictly inside the users gateway:

```typescript className="language-typescript" filename="src/http/users/gateway.ts"
import { defineGateway } from 'exisjs/router'
import { UsersRepository } from './repository'

export default defineGateway({
  // Provide the UsersRepository directly to this folder's DI container!
  providers: [
    ['UsersRepository', { useClass: UsersRepository }]
  ]
})
```

When ExisJS boots, it automatically discovers `gateway.ts`, parses the `providers`, and hydrates them into the internal Dependency Injection container before executing the routes. Inside your route handler, you can inject them:

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/users/route.ts"
import { controller, route } from 'exisjs/router'
import { inject } from 'exisjs/di'
import type { UsersRepository } from './repository'

export default controller({
  list: route.get('/', {
    async handle() {
      // Access the scoped dependency
      const usersRepo = inject<UsersRepository>('UsersRepository')
      return await usersRepo.findAll()
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/users/route.ts"
import { Controller, Get } from 'exisjs/decorators'
import { inject } from 'exisjs/di'
import type { UsersRepository } from './repository'

@Controller()
export default class UsersController {
  @Get('/')
  async list() {
    const usersRepo = inject<UsersRepository>('UsersRepository')
    return await usersRepo.findAll()
  }
}
```

### Imports & Plugins

Gateways allow you to bundle other modules and plugins into a domain.

### Functional Paradigm

```typescript className="language-typescript" filename="src/http/orders/gateway.ts"
import { defineGateway } from 'exisjs/router'
import AuthModule from '../auth/module'
import { stripePlugin } from '../../plugins/stripe'

export default defineGateway({
  // Pull in the Auth feature set
  imports: [AuthModule],
  
  // Isolate Stripe setup for the orders domain
  plugins: [stripePlugin({ apiKey: process.env.STRIPE_KEY })]
})
```

### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/orders/gateway.ts"
import { Gateway } from 'exisjs/decorators'
import AuthModule from '../auth/module'
import { stripePlugin } from '../../plugins/stripe'

@Gateway({
  // Pull in the Auth feature set
  imports: [AuthModule],
  
  // Isolate Stripe setup for the orders domain
  plugins: [stripePlugin({ apiKey: process.env.STRIPE_KEY })]
})
export default class OrdersGateway {}
```

<Hint>
- **Imports**: Automatically deduplicated. If multiple gateways import `AuthModule`, its internal singletons are only initialized once.
- **Plugins**: Setup logic runs specifically for the scoped folder.
</Hint>

## Gateway Inheritance (Cascading)

Gateways inherently **cascade**. If you define a Gateway at the absolute root (`src/http/gateway.ts`), it applies globally.

If you define another Gateway at `src/http/admin/gateway.ts`, requests to `/admin/dashboard` will sequentially pass through the Root Gateway, and *then* pass through the Admin Gateway!

```text className="language-text"
src/
└── http/
    ├── gateway.ts            <-- Runs first (Global Rate Limits)
    └── admin/
        ├── gateway.ts        <-- Runs second (JWT Validation)
        └── users/
            └── route.ts      <-- Runs last (Only if both gateways succeed!)
```

## Advanced Features

Gateways provide features to manage cross-cutting concerns like Exception Filters or Guards for an entire folder.

### 1. Folder-Scoped Guards

Apply Authorization Guards directly to a folder. If the guard returns `false`, the entire folder is protected.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { defineGateway } from 'exisjs/router'
import { RequireAdminRoleGuard } from '../../guards'

export default defineGateway({
  // Protects the entire /api folder
  guards: [RequireAdminRoleGuard]
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { Gateway } from 'exisjs/decorators'
import { RequireAdminRoleGuard } from '../../guards'

@Gateway({
  // Protects the entire /api folder
  guards: [RequireAdminRoleGuard]
})
export default class ApiGateway {}
```

### 2. Folder-Scoped Exception Filters

Catch exceptions for a specific domain. For example, you can return HTML error pages for `/views`, but standardized JSON errors for `/api`.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { defineGateway } from 'exisjs/router'
import { ApiVersion2ErrorFilter } from '../../filters'

export default defineGateway({
  // Catches all exceptions thrown inside /api/*
  filters: [ApiVersion2ErrorFilter]
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { Gateway } from 'exisjs/decorators'
import { ApiVersion2ErrorFilter } from '../../filters'

@Gateway({
  // Catches all exceptions thrown inside /api/*
  filters: [ApiVersion2ErrorFilter]
})
export default class ApiGateway {}
```

### 3. Folder-Scoped Interceptors

Transform or wrap all responses exiting a specific folder.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { defineGateway } from 'exisjs/router'
import { StandardResponseInterceptor } from '../../interceptors'

export default defineGateway({
  // Wraps all responses from /api/* in a standard format
  interceptors: [StandardResponseInterceptor]
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { Gateway } from 'exisjs/decorators'
import { StandardResponseInterceptor } from '../../interceptors'

@Gateway({
  // Wraps all responses from /api/* in a standard format
  interceptors: [StandardResponseInterceptor]
})
export default class ApiGateway {}
```

### 4. Bypassing Gateways (Exclude)

Bypass the Gateway's middleware, guards, and filters for specific sub-paths or methods without breaking your folder structure.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { defineGateway } from 'exisjs/router'

export default defineGateway({
  exclude: [
    '/api/public/status', // Exact Match
    '/api/webhooks/*',    // Wildcard Match
    { path: '/api/users', methods: ['GET'] } // Method-specific bypass
  ]
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/api/gateway.ts"
import { Gateway } from 'exisjs/decorators'

@Gateway({
  exclude: [
    '/api/public/status', // Exact Match
    '/api/webhooks/*',    // Wildcard Match
    { path: '/api/users', methods: ['GET'] } // Method-specific bypass
  ]
})
export default class ApiGateway {}
```

### 5. Dynamic Request Timeouts

Define dynamic, folder-scoped request timeouts. For example, give your `/reports` folder 60 seconds, but restrict `/api` to 5 seconds. You can evaluate the timeout dynamically per-request.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/reports/gateway.ts"
import { defineGateway } from 'exisjs/router'

export default defineGateway({
  // Dynamic request timeouts evaluated per-request
  timeout: (req) => req.headers['x-premium'] ? 30000 : 5000
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/reports/gateway.ts"
import { Gateway } from 'exisjs/decorators'

@Gateway({
  // Dynamic request timeouts evaluated per-request
  timeout: (req) => req.headers['x-premium'] ? 30000 : 5000
})
export default class ReportsGateway {}
```

### 6. Cascading Metadata

Define tags (like OpenAPI/Swagger tags or Role definitions) at the folder level that automatically cascade down to every route inside.

#### Functional Paradigm

```typescript className="language-typescript" filename="src/http/admin/gateway.ts"
import { defineGateway } from 'exisjs/router'

export default defineGateway({
  // Automatically cascades OpenAPI tags to every route in the folder
  metadata: {
    openapi: { tags: ['Admin API'], security: ['bearerAuth'] }
  }
})
```

#### Class-Based (OOP) Paradigm

```typescript className="language-typescript" filename="src/http/admin/gateway.ts"
import { Gateway } from 'exisjs/decorators'

@Gateway({
  // Automatically cascades OpenAPI tags to every route in the folder
  metadata: {
    openapi: { tags: ['Admin API'], security: ['bearerAuth'] }
  }
})
export default class AdminGateway {}
```
