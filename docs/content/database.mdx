# Database Layer

Unlike other Node.js frameworks that rely entirely on third-party ORMs like Prisma or TypeORM, **ExisJS ships with a fully integrated, efficient Database Layer.** 

This provides a massive advantage in developer experience and reliability, as connections, query generation, schema synchronization, and migrations are orchestrated directly by the framework.

<Info title="Functional vs OOP">
ExisJS natively supports both a **Functional Paradigm** and a **Class-Based OOP Paradigm** (for dependency injection and decorators). The database layer is seamlessly accessible through both approaches.
</Info>

## Setup and Connection

#### Functional Paradigm
```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { createDatabase } from 'exisjs/database'
import { userTable, leadCustomerTable } from '../database/schema'

export default exis({
  async onStart(app) {
    const database = createDatabase({
      dialect: 'postgres',
      url: process.env.DATABASE_URL,
      autoSync: true // Enables automatic schema synchronization!
    })
    
    // Register schemas for Auto-Sync
    database.registerSchema([userTable, leadCustomerTable])

    // Connect on boot
    await database.connect()
  }
})
```

#### Class-Based (OOP) Paradigm
```typescript filename="src/http/server.ts"
import { Server } from 'exisjs/decorators'
import { createDatabase } from 'exisjs/database'
import { userTable, leadCustomerTable } from '../database/schema'

@Server()
export default class RootServer {
  async onStart(app: App) {
    const database = createDatabase({
      dialect: 'postgres',
      url: process.env.DATABASE_URL,
      autoSync: true
    })
    
    database.registerSchema([userTable, leadCustomerTable])
    await database.connect()
  }
}
```

## SQL-First Schema Definition

ExisJS provides a strictly-typed, modern **SQL-First Schema API**. Instead of writing raw SQL migration files, you define your tables in TypeScript. When `autoSync` is enabled, ExisJS will read these definitions, diff them against your live PostgreSQL database, and automatically run `CREATE TABLE` and `ALTER TABLE` for you!

```typescript filename="src/database/schema.ts"
import { table, uuid, text, jsonb, timestamptz, boolean } from 'exisjs/database/sql'

export const userTable = table('user', {
  user_id: uuid('user_id').primaryKey().default('gen_random_uuid()'),
  name: text('name').notNull(),
  phone: text('phone').unique().notNull(),
  email: text('email').unique().notNull(),
  address: jsonb('address'),
  date_of_birth: timestamptz('date_of_birth'),
  role: text('role').notNull(),
  password_hash: text('password_hash').notNull(),
  created_at: timestamptz('created_at').default('NOW()')
})

export const leadCustomerTable = table('leadCustomer', {
  record_id: uuid('record_id').primaryKey().default('gen_random_uuid()'),
  name: text('name').notNull(),
  email: text('email'),
  is_customer: boolean('is_customer').default('false'),
  // Perfect, strict SQL Foreign Key References!
  assigned_to: uuid('assigned_to').references(() => userTable.user_id),
})
```

## Querying

ExisJS supports **two ways** to query your database. You can use the traditional string-based builder, or the new fully-typed SQL-First builder.

### Method A: Typed SQL-First Querying (Recommended)
This method gives you 100% type safety and auto-complete for your columns.

#### Functional Paradigm
```typescript filename="src/http/users/route.ts"
import { controller, route } from 'exisjs/router'
import { db } from 'exisjs/database'
import { eq } from 'exisjs/database/sql'
import { userTable } from '@/database/schema'

export default controller({
  list: route.get('/', {
    async handle() {
      // Fully typed! Auto-complete knows userTable has name, email, etc.
      const users = await db
        .select(userTable.user_id.name, userTable.name.name, userTable.email.name)
        .from(userTable)
        .where(eq(userTable.role, 'admin'))
        .limit(10)
        .rows()
        
      return users
    }
  }),

  create: route.post('/', {
    async handle({ req }) {
      const { name, email, phone, password_hash } = req.body
      
      const result = await db
        .insert(userTable)
        .values({ name, email, phone, role: 'user', password_hash })
        .returning(userTable.user_id.name)
        .execute()
        
      return { id: result.rows[0].user_id }
    }
  })
})
```

#### Class-Based (OOP) Paradigm
```typescript filename="src/http/users/service.ts"
import { Injectable } from 'exisjs/decorators'
import { db } from 'exisjs/database'
import { eq } from 'exisjs/database/sql'
import { userTable } from '@/database/schema'

@Injectable()
export class UsersService {
  async getAdmins() {
    return await db
      .select(userTable.user_id.name, userTable.name.name, userTable.email.name)
      .from(userTable)
      .where(eq(userTable.role, 'admin'))
      .limit(10)
      .rows()
  }

  async createUser(data: any) {
    const result = await db
      .insert(userTable)
      .values({ ...data, role: 'user' })
      .returning(userTable.user_id.name)
      .execute()
      
    return { id: result.rows[0].user_id }
  }
}
```

### Method B: String-Based Query Builder
If you don't want to define schema files, you can still use the raw string builder.

```typescript
// Query multiple rows
const users = await db.table('users')
  .select('id', 'name', 'email')
  .where('role', '=', 'admin')
  .orderBy('created_at', 'desc')
  .limit(10)
  .rows()
```

## Transactions

ExisJS makes it trivial to perform safe database transactions. If the callback throws an error, the transaction is automatically rolled back.

```typescript
import { db } from 'exisjs/database'

await db.transaction(async (tx) => {
  // Deduct from inventory
  await tx.execute(
    'UPDATE inventory SET stock = stock - $1 WHERE id = $2', 
    [1, itemId]
  )
  
  // Create order record
  await tx.execute(
    'INSERT INTO orders (user_id, item_id) VALUES ($1, $2)', 
    [userId, itemId]
  )
})
```

## Manual Migrations (Optional)

If you prefer to write raw SQL instead of using the Auto-Sync engine, ExisJS still includes a built-in migration tracker.

```typescript
import { db } from 'exisjs/database'

const migrator = db.getMigrator({ directory: './migrations' })

// Apply all pending migrations
await migrator.up()
```

A migration file simply exports `up` and `down` methods. You write raw SQL inside them for ultimate control.

```typescript filename="migrations/001_create_users.ts"
module.exports = {
  name: '001_create_users',
  async up(db) {
    await db.execute(`
      CREATE TABLE users (
        id SERIAL PRIMARY KEY,
        name VARCHAR(255) NOT NULL,
        email VARCHAR(255) UNIQUE NOT NULL
      )
    `)
  },
  async down(db) {
    await db.execute('DROP TABLE users')
  },
}
```

## API Reference

To maintain a clean namespace, ExisJS separates the core database manager from the SQL schema utilities.

### Core Database (`exisjs/database`)
Imports related to connection management, raw queries, and migrations.

- `db` - The global singleton database manager.
- `createDatabase` - Factory to instantiate a new database connection.
- `DatabaseManager` - The underlying class for `db`.
- `Migrator` - The migration engine class.
- `QueryBuilder` - The base query builder class.

### SQL-First Schema & Queries (`exisjs/database/sql`)
Imports related to defining tables, column types, and writing fluent queries.

**Table Builder:**
- `table` - Define a new SQL-first table.

**Column Types:**
- `uuid`
- `text`
- `varchar`
- `integer`
- `serial`
- `bigint`
- `numeric`
- `real`
- `boolean`
- `json`
- `jsonb`
- `timestamp`
- `timestamptz`
- `date`

**Condition Operators (for `.where()`):**
- `eq` (Equal: `=`)
- `ne` (Not Equal: `!=`)
- `gt` (Greater Than: `>`)
- `gte` (Greater Than or Equal: `>=`)
- `lt` (Less Than: `<`)
- `lte` (Less Than or Equal: `<=`)
- `isNull` (IS NULL)
- `isNotNull` (IS NOT NULL)
- `inArray` (IN)
