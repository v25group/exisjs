# Response Helpers & Streaming (`ExisResponse`)

ExisJS wraps standard Node.js `ServerResponse` objects in an `ExisResponse` instance (`res`). Handlers can return JavaScript objects or arrays directly for automatic JSON serialization, or use `res` methods for status codes, headers, cookie management, file downloads, streaming, and Server-Sent Events (SSE).

---

## Automatic JSON Serialization

When a route handler returns an object or array, ExisJS automatically serializes the data, sets `Content-Type: application/json; charset=utf-8`, and finishes the response:

### Functional Route

```typescript filename="src/http/users/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  listUsers: route.get('/', {
    handle: async () => {
      // Automatically serialized as JSON with 200 OK
      return [
        { id: 1, name: 'Alice' },
        { id: 2, name: 'Bob' },
      ]
    },
  }),
})
```

### Class-Based (OOP) Controller

```typescript filename="src/http/users/route.ts"
import { Controller, Get, ApiOperation } from 'exisjs/decorators'

@Controller()
export default class UsersController {
  @Get('/')
  @ApiOperation({ summary: 'List users' })
  async listUsers() {
    return [
      { id: 1, name: 'Alice' },
      { id: 2, name: 'Bob' },
    ]
  }
}
```

## Response Envelope Builders (`exisjs/response`)

ExisJS exports standardized response builders from `exisjs/response` to provide uniform `{ success: boolean, data?: any, error?: any, meta?: any }` structures across all endpoints:

| Builder | HTTP Status | Response Structure | Description |
| :--- | :--- | :--- | :--- |
| `success(data, message?, meta?)` | `200 OK` | `{ success: true, data, message?, meta? }` | Standard successful response |
| `created(data, message?, meta?)` | `201 Created` | `{ success: true, data, message: 'Created', meta? }` | Newly created entity |
| `accepted(data?, message?, meta?)` | `202 Accepted` | `{ success: true, data, message: 'Accepted', meta? }` | Asynchronous or queued action |
| `noContent()` | `204 No Content` | `{ success: true, data: null }` | Action succeeded with no payload |
| `error(message, code?, details?, status?)` | `4xx / 5xx` | `{ success: false, error: { message, code?, details? } }` | Structured error envelope |
| `problem(title, status, detail?, opts?)` | Custom | RFC 7807 / RFC 9457 Problem Details object | Standardized HTTP Problem Details |
| `paginate(items, total, options)` | `200 OK` | `{ success: true, data, pagination: { ... } }` | Paginated response envelope |

### Example Usage

```typescript filename="src/http/users/route.ts"
import { controller, route } from 'exisjs/router'
import { success, created, error, HttpStatus } from 'exisjs/response'

export default controller({
  getUser: route.get('/:id', {
    handle: async ({ params, res }) => {
      const user = await db.users.find(params.id)
      if (!user) {
        res.status(HttpStatus.NOT_FOUND)
        return error('User not found', 'NOT_FOUND')
      }
      return success(user, 'User retrieved')
    },
  }),

  createUser: route.post('/', {
    handle: async ({ body, res }) => {
      const user = await db.users.create(body)
      res.status(HttpStatus.CREATED)
      return created(user, 'User registered')
    },
  }),
})
```

## RFC 7807 / RFC 9457 Problem Details

For public or enterprise REST APIs, `problem()` generates standard Problem Details objects:

```typescript filename="src/http/checkout/route.ts"
import { controller, route } from 'exisjs/router'
import { problem, HttpStatus } from 'exisjs/response'

export default controller({
  checkout: route.post('/', {
    handle: async ({ req, res }) => {
      res.status(HttpStatus.UNPROCESSABLE_ENTITY)
      return problem(
        'Out of Stock',
        422,
        'One or more requested items are no longer available in inventory.',
        {
          type: 'https://api.example.com/errors/inventory',
          instance: req.path,
          unavailableItems: ['item_101', 'item_204'],
        }
      )
    },
  }),
})
```

## Standardized Pagination (`paginate`)

The `paginate()` helper combines a data array with calculated total counts to produce a uniform pagination object:

```typescript filename="src/http/products/route.ts"
import { controller, route } from 'exisjs/router'
import { paginate, getPaginationSkip, tex } from 'exisjs/validator'

const QuerySchema = tex.pagination({ defaultLimit: 20, maxLimit: 100 })

export default controller({
  list: route.get('/', {
    query: QuerySchema,
    handle: async ({ query }) => {
      const { skip, limit, page } = getPaginationSkip(query)

      const [items, total] = await Promise.all([
        db.products.findMany({ skip, take: limit }),
        db.products.count(),
      ])

      return paginate(items, total, { page, limit })
    },
  }),
})
```

## Setting Headers & Status Codes

`ExisResponse` methods can be chained:

```typescript
res.status(404)
   .set('X-Custom-Header', 'custom-value')
   .append('Set-Cookie', 'pref=dark')
   .json({ error: 'Not Found' })
```

### Header Methods

- `res.status(code)`: Sets the numeric HTTP status code.
- `res.set(name, value)` / `res.header(name, value)`: Sets a header.
- `res.append(name, value)`: Appends to a header (e.g. multiple `Set-Cookie` directives).
- `res.type(mimeType)`: Shorthand for setting `Content-Type` (e.g. `res.type('html')` $\to$ `text/html`).
- `res.removeHeader(name)`: Removes a previously set header.
- `res.vary(field)`: Adds a field to the `Vary` caching header.

## Cookie Management

Set and clear cookies with modern web standard options (including CHIPS Partitioning and Priority hints):

### Setting Cookies

```typescript
// Standard secure HTTP-only cookie
res.cookie('token', 'xyz123', {
  maxAge: 86400, // 24 hours in seconds
  httpOnly: true,
  secure: true,
  sameSite: 'Strict',
  path: '/',
})

// Cross-site iframe cookie with CHIPS partitioning
res.cookie('embed_pref', 'theme_dark', {
  sameSite: 'None', // Forces secure: true automatically
  partitioned: true, // Cookies Having Independent Partitioned State (CHIPS)
  priority: 'high',
  path: '/',
})
```

### Clearing Cookies

```typescript
res.clearCookie('token', { path: '/' })
```

#### Cookie Options

| Option | Type | Description |
| :--- | :--- | :--- |
| `maxAge` | `number` | Expiration time in seconds from current time |
| `expires` | `Date` | Absolute expiration date |
| `httpOnly` | `boolean` | Flags cookie as inaccessible to client scripts |
| `secure` | `boolean` | Requires HTTPS transport (forced if `sameSite: 'None'`) |
| `sameSite` | `'Strict' \| 'Lax' \| 'None' \| boolean` | Cross-site request cookie behavior |
| `partitioned` | `boolean` | Enables CHIPS cookie partitioning |
| `priority` | `'low' \| 'medium' \| 'high'` | Storage priority under client disk pressure |
| `path` | `string` | URL path scope (default: `'/'`) |
| `domain` | `string` | Domain scope for the cookie |

## File Downloads & Streaming

### File Downloads

Return `download()` from a handler to send generated content (a string, `Buffer` or stream) as an attachment. It sets `Content-Disposition` and infers `Content-Type` from the filename:

```typescript filename="src/http/reports/route.ts"
import { controller, route } from 'exisjs/router'
import { download } from 'exisjs/response'

export default controller({
  exportCsv: route.get('/export', {
    async handle() {
      const csv = await ReportService.buildCsv()
      return download(csv, 'report.csv')
    },
  }),
  exportXlsx: route.get('/export.xlsx', {
    async handle() {
      const stream = await ReportService.streamWorkbook()
      return download(stream, 'report.xlsx', {
        headers: { 'Cache-Control': 'no-store' },
      })
    },
  }),
})
```

Pass `{ contentType }` to override the inferred MIME type. A handler that returns a plain `Buffer` sends it as `application/octet-stream`.

#### Files on disk: `res.download(path)`

`res.download()` sends a file from disk. A string argument is **always a file path**, never content; a missing file answers `404`. It also accepts a `Buffer` or stream.

```typescript filename="src/http/reports/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  annual: route.get('/annual', {
    handle: async ({ res }) => {
      res.download('./storage/annual-report.pdf', 'Annual-Report-2026.pdf')
    },
  }),
  // The filename comes from the request, so confine it to one directory
  byName: route.get('/files/:name', {
    handle: async ({ params, res }) => {
      res.download(params.name, undefined, { root: './storage/exports' })
    },
  }),
})
```

> **Security:** whenever any part of the path comes from the request (a param, query value or body field), pass `root`. Paths that resolve outside it, such as `../../.env` or an absolute path, answer `404` instead of leaking the file.

| | String argument means | Use for |
| :--- | :--- | :--- |
| `return download(data, name)` | Content | Generated CSV, JSON, reports |
| `res.download(path, name?, { root })` | File path | Files stored on disk |

### Stream Piping (`res.stream()` / `res.sendStream()`)

ExisJS supports direct streaming for:
- Node.js `Readable` streams (`fs.createReadStream`, database cursor streams)
- Web standard `ReadableStream` (OpenAI SDK, fetch responses)
- `AsyncIterable` and async generators

#### 1. Streaming Node.js Readable Streams

```typescript filename="src/http/export/route.ts"
import { controller, route } from 'exisjs/router'
import fs from 'node:fs'

export default controller({
  exportCsv: route.get('/', {
    handle: ({ res }) => {
      const stream = fs.createReadStream('./data/export.csv')
      res.type('text/csv')
      res.stream(stream)
    },
  }),
})
```

#### 2. Streaming Web Standard Streams (AI Chat & Fetch)

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  chat: route.post('/', {
    handle: async ({ req, res }) => {
      const upstream = await fetch('https://api.openai.com/v1/chat/completions', {
        method: 'POST',
        headers: {
          'Authorization': `Bearer ${process.env.OPENAI_API_KEY}`,
          'Content-Type': 'application/json',
        },
        body: JSON.stringify({
          model: 'gpt-4o',
          stream: true,
          messages: req.body.messages,
        }),
      })

      res.type('text/event-stream')
      res.stream(upstream.body!)
    },
  }),
})
```

#### 3. Automatic Return Stream Piping

If a route handler returns a `Readable` stream directly, ExisJS detects and pipes it automatically:

```typescript filename="src/http/files/route.ts"
import { controller, route } from 'exisjs/router'
import fs from 'node:fs'

export default controller({
  getFile: route.get('/', {
    handle: () => {
      return fs.createReadStream('./data/report.csv')
    },
  }),
})
```

## Server-Sent Events (SSE)

Use `res.sse()` to open a real-time event stream:

```typescript filename="src/http/events/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  liveFeed: route.get('/', {
    handle: ({ res }) => {
      const sse = res.sse()

      sse.send({ event: 'connected', data: { timestamp: Date.now() } })

      const interval = setInterval(() => {
        sse.send({ event: 'price', data: { symbol: 'BTC', price: 95000 } })
      }, 1000)

      sse.onClose(() => {
        clearInterval(interval)
      })
    },
  }),
})
```

### Streaming Async Iterables with `sse.pipeFrom()`

Stream chunks from an async generator or AI SDK directly:

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  streamTokens: route.post('/', {
    handle: ({ res }) => {
      res.sse(async (sse) => {
        async function* tokenGenerator() {
          yield 'Hello '
          yield 'from '
          yield 'ExisJS SSE!'
        }

        await sse.pipeFrom(tokenGenerator(), (chunk) => ({
          event: 'token',
          data: { text: chunk },
        }))

        sse.close()
      })
    },
  }),
})
```
