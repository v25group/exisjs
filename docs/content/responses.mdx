# Responses

Unlike standard Node.js `ServerResponse` objects, ExisJS wraps every response in an `ExisResponse` class. It provides a chainable API while maintaining the raw performance of native Node.

While ExisJS routes allow you to simply `return { data: ... }` (which automatically serializes to JSON), the `res` object gives you granular control over headers, cookies, streams, and file downloads.

---

## 1. Returning Data vs Sending Data

The most common way to respond to a request in ExisJS is to simply **return an object or array**. ExisJS intercepts the return value, automatically serializes it to JSON, sets the `Content-Type`, calculates the `Content-Length`, and sends it down the wire.

#### Functional Paradigm

```typescript filename="src/http/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  getUsers: route.get('/', {
    handle(req, res) {
      // ExisJS automatically handles JSON serialization
      return [{ id: 1, name: "Alice" }] 
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Get } from 'exisjs/decorators'

@Controller()
export default class UsersController {
  @Get('/')
  async getUsers() {
    // ExisJS automatically handles JSON serialization
    return [{ id: 1, name: "Alice" }] 
  }
}
```

However, you can completely bypass this and use the `res` object manually:

#### Functional Paradigm

```typescript filename="src/http/route.ts"
export default controller({
  getUsers: route.get('/', {
    handle(req, res) {
      // Chainable response API
      res.status(201).json([{ id: 1, name: "Alice" }])
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Get, Res } from 'exisjs/decorators'

@Controller()
export default class UsersController {
  @Get('/')
  async getUsers(@Res() res: any) {
    // Chainable response API
    res.status(201).json([{ id: 1, name: "Alice" }])
  }
}
```

## 2. Standardized JSON Responses (`exisjs/response`)

To keep your APIs consistent and predictable across teams, ExisJS provides standard response helpers, envelope constructors, status code constants, and RFC 7807 problem details in `exisjs/response` (also re-exported from the root `exisjs` package).

Using these ensures your entire backend adheres to a clean, strongly-typed `{ success: boolean, data?: any, error?: any, meta?: any }` structure that frontend clients and SDK generators can reliably consume.

### Available Response Builders

| Builder | HTTP Status | Envelope / Output | Purpose |
| :--- | :--- | :--- | :--- |
| `success(data, message?, meta?)` | 200 OK | `{ success: true, data, message?, meta? }` | Standard successful payload |
| `created(data, message?, meta?)` | 201 Created | `{ success: true, data, message: 'Created', meta? }` | Created resource |
| `accepted(data?, message?, meta?)` | 202 Accepted | `{ success: true, data, message: 'Accepted', meta? }` | Queued async/background job |
| `noContent()` | 204 No Content | `{ success: true, data: null }` | Empty successful action |
| `error(msg, code?, details?, status?)` | 4xx / 5xx | `{ success: false, error: { message, code?, details?, status? } }` | Structured error envelope |
| `problem(title, status, detail?, opts?)` | Custom | RFC 7807 / RFC 9457 Problem Details object | Standard API problem specification |
| `paginate(items, total, options)` | 200 OK | `{ success: true, data: items, pagination: { ... } }` | Standard pagination envelope |
| `getPaginationSkip(query)` | N/A | `{ skip, limit, page }` | Database offset/limit calculator |
| `json(data, status?, headers?)` | Custom | `{ data, status, headers }` | Typed JSON payload descriptor |
| `redirect(url, status?)` | 3xx | `{ redirect, status }` | Redirection descriptor |

#### Functional Paradigm Example

```typescript filename="src/http/route.ts"
import { controller, route } from 'exisjs/router'
import { success, created, error, HttpStatus } from 'exisjs/response'

export default controller({
  getUser: route.get('/:id', {
    handle(req, res) {
      const user = db.users.find(req.params.id)
      
      if (!user) {
        res.status(HttpStatus.NOT_FOUND)
        // Generates: { success: false, error: { message: "User not found", code: "NOT_FOUND" } }
        return error("User not found", "NOT_FOUND")
      }
      
      // Generates: { success: true, data: { id: 1, name: "Alice" }, message: "Found user" }
      return success(user, "Found user")
    }
  }),

  createUser: route.post('/', {
    handle(req, res) {
      const user = db.users.create(req.body)
      res.status(HttpStatus.CREATED)
      // Generates: { success: true, data: user, message: "User registered" }
      return created(user, "User registered")
    }
  })
})
```

#### Class-Based (OOP) Paradigm Example

```typescript filename="src/http/route.ts"
import { Controller, Get, Post, Param, Body, Res } from 'exisjs/decorators'
import { success, created, error, HttpStatus } from 'exisjs/response'

@Controller()
export default class UsersController {
  @Get('/:id')
  async getUser(@Param('id') id: string, @Res() res: any) {
    const user = db.users.find(id)
    
    if (!user) {
      res.status(HttpStatus.NOT_FOUND)
      return error("User not found", "NOT_FOUND")
    }
    
    return success(user, "Found user")
  }

  @Post('/')
  async createUser(@Body() body: any, @Res() res: any) {
    const user = db.users.create(body)
    res.status(HttpStatus.CREATED)
    return created(user, "User created successfully")
  }
}
```

### RFC 7807 / RFC 9457 Problem Details (`problem`)

For enterprise and public REST APIs requiring standardized error models, `problem()` produces RFC-compliant Problem Details:

```typescript
import { problem, HttpStatus } from 'exisjs/response'

res.status(HttpStatus.UNPROCESSABLE_ENTITY)
return problem('Invalid Request Parameters', 422, 'One or more fields failed schema validation', {
  type: 'https://api.example.com/errors/validation',
  instance: req.url,
  invalidParams: [
    { name: 'email', reason: 'Must be a valid email address' },
    { name: 'age', reason: 'Must be greater than 18' }
  ]
})
```

## 3. Standardized Pagination Envelopes (`paginate`)

To eliminate pagination inconsistency across different endpoints, ExisJS exports standard `paginate()` and `getPaginationSkip()` utilities directly from `exisjs/validator` (as well as `exisjs/response`).

#### Functional Paradigm

```typescript filename="src/http/products/route.ts"
import { controller, route } from 'exisjs/router'
import { tex, paginate, getPaginationSkip } from 'exisjs/validator'

export default controller({
  listProducts: route.get('/', {
    query: tex.pagination({ defaultLimit: 15, maxLimit: 50 }),
    async handle({ query }) {
      // 1. Automatically extracts { skip, limit, page } with fallback defaults
      const { skip, limit, page } = getPaginationSkip(query)

      // 2. Fetch items and count total from your database
      const [items, total] = await Promise.all([
        db.product.findMany({ skip, take: limit, orderBy: { createdAt: 'desc' } }),
        db.product.count(),
      ])

      // 3. Return standardized pagination envelope
      return paginate(items, total, { page, limit })
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/products/route.ts"
import { Controller, Get, Query } from 'exisjs/decorators'
import { tex, paginate, getPaginationSkip } from 'exisjs/validator'

const ProductQuerySchema = tex.pagination({ defaultLimit: 15, maxLimit: 50 })

@Controller('/products')
export default class ProductsController {
  @Get('/', { query: ProductQuerySchema })
  async listProducts(@Query() query: any) {
    const { skip, limit, page } = getPaginationSkip(query)

    const [items, total] = await Promise.all([
      db.product.findMany({ skip, take: limit, orderBy: { createdAt: 'desc' } }),
      db.product.count(),
    ])

    return paginate(items, total, { page, limit })
  }
}
```

### The Standardized Pagination Envelope

Calling `paginate(items, total, { page, limit })` produces a uniform envelope:

```json
{
  "data": [
    { "id": 1, "name": "Mechanical Keyboard" },
    { "id": 2, "name": "Ergonomic Mouse" }
  ],
  "pagination": {
    "page": 1,
    "limit": 15,
    "total": 42,
    "totalPages": 3,
    "hasNext": true,
    "hasPrev": false,
    "hasNextPage": true,
    "hasPrevPage": false
  }
}
```

Both `hasNext`/`hasPrev` and `hasNextPage`/`hasPrevPage` are provided out-of-the-box, ensuring full compatibility with both cursor-style and page-number frontend UI components.

## 4. Setting Headers & Status

The `ExisResponse` object implements a chainable API for HTTP headers and status codes.

```typescript
res.status(404)
   .set('X-Custom-Header', 'exis-is-awesome')
   .append('Set-Cookie', 'foo=bar')
   .json({ error: 'Not Found' })
```

### Supported Header Methods
- `res.status(code)`: Sets the HTTP status code.
- `res.set(key, value)` (or `res.header()`): Sets an HTTP header.
- `res.append(key, value)`: Appends to an existing header (e.g., multiple `Set-Cookie` directives).
- `res.removeHeader(key)`: Deletes a header.
- `res.type(mimeType)`: A shorthand for setting the `Content-Type` header (e.g., `res.type('html')` becomes `text/html`).
- `res.vary(field)`: Adds a field to the `Vary` header for caching.

## 3. Cookies

ExisJS provides native helper methods for setting and clearing cookies safely, supporting modern web standards including CHIPS (Partitioned Cookies) and Priority hints.

### Setting Cookies

```typescript
// Set a secure, HTTP-only session cookie
res.cookie('session_id', '123456', {
  maxAge: 86400, // 1 day in seconds
  httpOnly: true,
  secure: true,
  sameSite: 'Strict'
})

// Cross-site embedded iframe cookie with CHIPS (Partitioned)
res.cookie('widget_pref', 'dark_mode', {
  sameSite: 'None', // Automatically forces `secure: true` per modern browser specs
  partitioned: true, // Cookies Having Independent Partitioned State (CHIPS)
  priority: 'high',  // Hints browser cookie retention under storage pressure ('low' | 'medium' | 'high')
  path: '/'
})
```

#### Cookie Options Reference

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `maxAge` | `number` | `undefined` | Lifetime of the cookie in seconds (sets both `Max-Age` and computed `Expires`). |
| `expires` | `Date` | `undefined` | Absolute expiration date for the cookie. |
| `httpOnly` | `boolean` | `false` | Mitigates XSS by preventing client-side JavaScript access. |
| `secure` | `boolean` | `false` | Requires HTTPS. *Automatically set to `true` if `sameSite: 'None'` is provided.* |
| `sameSite` | `'Strict' \| 'Lax' \| 'None' \| boolean` | `undefined` | Controls cross-site request cookie inclusion. |
| `partitioned` | `boolean` | `false` | Enables CHIPS for third-party contexts across top-level site partitions. |
| `priority` | `'low' \| 'medium' \| 'high'` | `undefined` | RFC 6265bis storage priority hint when client cookie capacity is exhausted. |
| `path` | `string` | `'/'` | Path where the cookie is valid. |
| `domain` | `string` | `undefined` | Domain scope for the cookie. |

### Clearing Cookies

When clearing cookies, browsers require the matching `path` and `domain` used when the cookie was originally set:

```typescript
// Clear default root cookie
res.clearCookie('session_id')

// Clear scoped cookie matching original domain & path
res.clearCookie('tenant_token', {
  path: '/api',
  domain: '.example.com'
})
```

## 4. File Downloads & Streaming

ExisJS makes streaming files simple, bypassing V8 memory bottlenecks by piping native Node streams directly to the socket with automated resource cleanup.

### `res.download()`
Automatically reads a file from disk, sets the `Content-Disposition` header to force a download in the browser, and infers the correct MIME type based on the file extension.

#### Functional Paradigm

```typescript
import { controller, route } from 'exisjs/router'

export default controller({
  downloadReport: route.get('/report', {
    handle(req, res) {
      res.download('/absolute/path/to/report.pdf', 'Q4-Report.pdf')
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript
import { Controller, Get, Res } from 'exisjs/decorators'

@Controller()
export default class ReportController {
  @Get('/report')
  async downloadReport(@Res() res: any) {
    res.download('/absolute/path/to/report.pdf', 'Q4-Report.pdf')
  }
}
```

### `res.sendStream()` & `res.stream()`
ExisJS provides first-class streaming support across `res.sendStream()` (aliased as `res.stream()`), accepting:
- **Node.js `Readable` streams** (e.g. `fs.createReadStream`, database cursors, zlib streams)
- **Web Standard `ReadableStream`** (e.g. from `fetch()`, OpenAI SDK, Anthropic SDK, and AI frameworks)
- **`AsyncIterable` & Async Generators** (e.g. `async function* generate() { yield ... }`)

#### Core Reliability Guarantees:
- **Socket Backpressure Control**: If the underlying network socket buffer fills up (`res.raw.write()` returns `false`), ExisJS automatically pauses stream consumption until the `'drain'` event fires, preventing fast producers from exhausting server RAM.
- **Client Disconnect Teardown**: If the client aborts or closes the connection prematurely (`req.raw.on('close')`), ExisJS cancels Web stream readers (`reader.cancel()`), destroys Node streams (`stream.destroy()`), or terminates async generators (`generator.return()`).
- **Resilient Error Trapping**: Stream transmission failures are trapped without crashing the Node.js process. If headers have not yet been sent, a structured 500 error envelope is returned.

#### 1. Streaming Node.js Readable Streams

##### Functional Paradigm
```typescript filename="src/http/video/route.ts"
import { controller, route } from 'exisjs/router'
import fs from 'node:fs'

export default controller({
  streamVideo: route.get('/', {
    handle(req, res) {
      const videoStream = fs.createReadStream('/path/to/video.mp4')
      res.type('video/mp4')
      res.sendStream(videoStream)
    }
  })
})
```

## 6. ETags & Conditional Requests (304 Not Modified)

ExisJS features native, automatic ETag generation. 

If the client sends an `If-None-Match` header matching the ETag of the current response, ExisJS will immediately abort serialization and send a `304 Not Modified` header with an empty body, saving bandwidth and CPU cycles.

*Note: ETag generation is disabled by default, but can be enabled globally in your `exis()` config, or manually per-route via `res.etagEnabled = true`.*

## 7. Server-Sent Events (SSE) & AI Streaming

ExisJS provides a first-class `res.sse()` method for real-time live events and AI chat completions (OpenAI, Anthropic, Ollama, LangChain).

When called, `res.sse()` automatically configures and flushes the required HTTP headers:
- `Content-Type: text/event-stream; charset=utf-8`
- `Cache-Control: no-cache, no-transform`
- `Connection: keep-alive`
- `X-Accel-Buffering: no` (disables NGINX proxy buffering)

You can import `SSEStream`, `formatSSEEvent`, `SSEMessage`, and `SSEOptions` from `exisjs/router`.

### Basic SSE Stream

#### Functional Paradigm

```typescript filename="src/http/events/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  liveEvents: route.get('/', {
    handle(req, res) {
      // Initialize the stream (heartbeat ping every 15s by default)
      const sse = res.sse()

      sse.send({ event: 'connected', data: { timestamp: Date.now() } })

      const interval = setInterval(() => {
        sse.send({ event: 'price-update', data: { symbol: 'BTC', price: 95000 } })
      }, 1000)

      // Automatically clean up intervals when the client disconnects or closes the tab
      sse.onClose(() => {
        clearInterval(interval)
      })
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/events/route.ts"
import { Controller, Get, Res } from 'exisjs/decorators'
import type { Response } from 'exisjs/router'

@Controller()
export default class EventsController {
  @Get('/events')
  streamEvents(@Res() res: Response) {
    const sse = res.sse()

    sse.send({ event: 'connected', data: { status: 'ok' } })

    sse.onClose(() => {
      console.log('Client disconnected from SSE stream')
    })
  }
}
```

### AI / LLM Streaming with `sse.pipeFrom()`

You can directly stream chunks from any `AsyncIterable` (such as the OpenAI SDK, Anthropic SDK, or custom async generators) using `sse.pipeFrom()`:

#### Functional Paradigm

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  chat: route.post('/', {
    handle(req, res) {
      res.sse(async (sse) => {
        // Stream directly from an async generator or AI SDK
        async function* generateTokens() {
          yield 'Hello'
          yield ' from'
          yield ' ExisJS'
          yield ' AI streaming!'
        }

        await sse.pipeFrom(generateTokens(), (token) => ({
          event: 'delta',
          data: { text: token }
        }))

        sse.close()
      })
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/ai/route.ts"
import { Controller, Post, Res } from 'exisjs/decorators'
import type { Response } from 'exisjs/router'

@Controller('/ai')
export default class AiController {
  @Post('/chat')
  chat(@Res() res: Response) {
    res.sse(async (sse) => {

        yield ' from'
        yield ' ExisJS'

      }

        event: 'delta',
        data: { text: token }

```

### SSE Options & Methods

- `res.sse(options?)`: Options include:
  - `heartbeat`: Heartbeat interval in milliseconds (default: `15000`). Pass `false` to disable.
  - `heartbeatComment`: Custom comment string for keep-alive pings (default: `": ping\n\n"`).
  - `headers`: Additional custom HTTP headers.
- `sse.send(message)`: Sends an event. Accepts string, number, object (auto JSON-stringified), or `{ event, data, id, retry }`.
- `sse.comment(text)`: Sends a raw SSE comment line (e.g. `: ping\n\n`) without triggering client-side event listeners.
- `sse.onClose(callback)`: Registers a callback fired when the client disconnects.
- `sse.close()`: Gracefully terminates the stream and closes the HTTP response.
