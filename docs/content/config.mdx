# Configuration (`exis.config.ts`)

ExisJS uses a typed configuration file located at the project root (`exis.config.ts` or `exis.config.js`). It controls global server behavior, middleware defaults, file watcher options, cluster concurrency, and runtime environments.

---

## Static Configuration

Export the result of `defineConfig()` from `exis.config.ts` for full TypeScript type safety and autocompletion:

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default defineConfig({
  port: 4000,
  host: '0.0.0.0',

  cors: {
    origin: ['https://example.com', 'https://admin.example.com'],
    credentials: true,
    methods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE']
  },

  logger: {
    level: 'info',
    pretty: true
  },

  helmet: {
    enabled: true,
    xFrameOptions: 'SAMEORIGIN'
  },

  bodyLimit: 10 * 1024 * 1024 // 10MB
})
```

## Dynamic Phase-Based Configuration

ExisJS supports exporting an asynchronous function that receives the current lifecycle `phase` and the framework's default configuration:

```typescript filename="exis.config.ts"
import {
  defineConfig,
  PHASE_DEVELOPMENT_SERVER,
  PHASE_PRODUCTION_SERVER,
  PHASE_TEST
} from 'exisjs/config'

export default async (phase: string, { defaultConfig }: any) => {
  const isDev = phase === PHASE_DEVELOPMENT_SERVER
  const isTest = phase === PHASE_TEST

  return defineConfig({
    port: Number(process.env.PORT) || 4000,

    logger: isDev
      ? { level: 'debug', pretty: true }
      : isTest
        ? false
        : { level: 'info', pretty: false },

    compression: !isDev && !isTest,

    cluster: {
      workers: phase === PHASE_PRODUCTION_SERVER ? 'auto' : 1
    }
  })
}
```

### Lifecycle Phase Constants

| Constant | Value | Triggered By |
| :--- | :--- | :--- |
| `PHASE_DEVELOPMENT_SERVER` | `'phase-development-server'` | `exisjs dev` |
| `PHASE_PRODUCTION_SERVER` | `'phase-production-server'` | `exisjs start` |
| `PHASE_PRODUCTION_BUILD` | `'phase-production-build'` | `exisjs build` |
| `PHASE_TEST` | `'phase-test'` | `exisjs test` / `NODE_ENV=test` |

## Environment Variable Management

ExisJS automatically loads and expands `.env` files in cascade priority:

1. `.env.${NODE_ENV}.local`
2. `.env.local` (ignored when `NODE_ENV=test`)
3. `.env.${NODE_ENV}`
4. `.env`

### Type-Safe Validation with `tex`

To ensure configuration values are valid before starting the HTTP server:

```typescript filename="src/config/env.ts"
import { tex } from 'exisjs/validator'

export const env = tex
  .object({
    PORT: tex.number({ coerce: true, default: 4000 }),
    NODE_ENV: tex.enum(['development', 'production', 'test'], { default: 'development' }),
    DATABASE_URL: tex.string(),
    REDIS_URL: tex.string({ optional: true })
  })
  .parse(process.env)
```

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'
import { env } from './src/config/env'

export default defineConfig({
  port: env.PORT,
  env: env.NODE_ENV
})
```

## Configuration Options Reference

### Network & Transport

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `port` | `number` | `4000` | Port number to bind the HTTP server to. |
| `host` | `string` | `'0.0.0.0'` | Network host interface. |
| `server` | `'auto' \| 'node' \| 'bun' \| 'uws'` | `'auto'` | Underlying server adapter engine. |
| `ssl` | `{ key: string \| Buffer, cert: string \| Buffer }` | `undefined` | SSL certificate credentials for native HTTPS. |
| `http2` | `boolean` | `true` | Enables HTTP/2 (active when SSL is configured). |
| `redirectHttp` | `boolean \| number` | `false` | Automatically redirects plaintext HTTP traffic to HTTPS. |
| `trustProxy` | `boolean \| number` | `false` | Trust proxy headers. `true` trusts every hop (including CDN headers); a number `N` trusts the N closest hops, counting the socket peer. |
| `keepAlive` | `boolean \| KeepAliveConfig` | `false` | Configures socket keep-alive (`timeoutMs`, `headersTimeoutMs`, `maxRequests`). |

### Middleware Defaults & Security

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `cors` | `boolean \| CorsConfig` | `{ origin: '*' }` | Global CORS policy. Can be overridden in boundaries or routes. `credentials: true` requires explicit origins: with `origin: '*'` it is ignored and a warning is logged, because browsers reject that combination. |
| `helmet` | `boolean \| HelmetConfig` | `{ enabled: true }` | Security headers (CSP, X-Frame-Options, HSTS). |
| `compression` | `boolean` | `false` | Gzip/Brotli HTTP response compression. |
| `bodyLimit` | `number` | `10485760` (10MB) | Maximum request payload body size in bytes. |
| `blockSuspiciousProbes` | `boolean \| BlockProbesOptions` | `false` | Blocks known vulnerability scanners and malicious probes (`.php`, `wp-admin`). |
| `etag` | `boolean` | `false` | Generates weak ETags for cache validation on responses. |
| `transformResponse` | `boolean \| Function` | `false` | Standardizes handler response payload envelopes. |

### Logging & Diagnostics

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `logger` | `boolean \| LoggerConfig` | `false` | Pino logger settings (`level`, `pretty`, `redact`). |
| `debugRouting` | `boolean` | `false` | Outputs detailed route resolution logs per request in development. |
| `asyncContext` | `boolean` | `false` | Enables `AsyncLocalStorage` context tracking (`getContext()`). |
| `docs` / `swagger` | `boolean \| SwaggerConfig` | `{ enabled: false }` | OpenAPI 3.1 specification and Swagger UI endpoint generation. Served in every environment when enabled; use `enabled: process.env.NODE_ENV !== 'production'` to hide it in production. |
| `healthcheck` | `boolean \| HealthCheckConfig` | `{ enabled: false }` | System health endpoint (`path: '/_health'`). |
| `metrics` | `boolean \| MetricsConfig` | `{ enabled: false }` | Prometheus metrics endpoint (`path: '/metrics'`). |
| `telemetry` | `boolean \| TelemetryConfig` | `{ enabled: false }` | OpenTelemetry tracing and metrics export. |

### Concurrency & Clustering

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default defineConfig({
  cluster: {
    // 1 (single-threaded), 'safe' (up to 2 cores), 'auto'/'max' (all available CPU cores)
    workers: 'auto'
  }
})
```

## File Watcher & Development Configuration

The development server (`exisjs dev`) provides file watching with debounce and ignore rules:

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default defineConfig({
  watch: {
    paths: ['src', '.env'],
    ignore: [/tests\//, 'temp/**'],
    extensions: ['.ts', '.tsx', '.js', '.json'],
    debounceMs: 250
  },

  dev: {
    usePolling: false, // Set to true for network mounts or WSL
    interval: 100
  }
})
```

### Automatically Excluded Artifacts

ExisJS automatically excludes build output and temp folders from triggering watcher reloads:
- **Folders**: `node_modules`, `.git`, `.exis`, `dist`, `build`, `out`, `.turbo`, `.next`, `.cache`, `logs`, `tmp`, `temp`, `tests`, `coverage`.
- **Files**: `.log`, `.sqlite`, `.db`, `.png`, `.jpg`, `.svg`, `package-lock.json`, `*.d.ts`.

## Plugin Integration

Plugins extend framework capabilities by intercepting server configuration or registering global routes:

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'
import { defineModule } from 'exisjs/module'

const metricsPlugin = defineModule({
  name: 'custom-metrics',
  routes: (app) => {
    app.get('/metrics/live', (req, res) => {
      res.json({ memory: process.memoryUsage() })
    })
  }
})

export default defineConfig({
  plugins: [metricsPlugin]
})
```

## Graceful Process Termination

ExisJS automatically listens for `SIGTERM` and `SIGINT` signals in containerized environments:

1. Closes the HTTP server listener to stop accepting incoming traffic.
2. Closes idle keep-alive sockets and waits for in-flight requests to finish (up to the shutdown timeout).
3. Runs shutdown hooks in order: `app.onShutdown()` hooks (including `onDestroy` / `onApplicationShutdown(signal)` on injectable services), then `onClose` hooks.
4. Disconnects every database registered with `registerDatabase()`, once each.
5. Stops cron jobs and exits.

Use `onClose` for resources ExisJS does not manage, such as browser sessions, queues or worker threads:

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { scraper } from '../workers/scraper'

export default exis({
  async onStart(app) {
    // Receives the signal name ('SIGTERM', 'SIGINT') when one triggered the shutdown
    app.onShutdown(async (signal) => {
      app.log.info({ signal }, 'stopping background workers')
      await scraper.stop()
    })
  },
  async onClose(app) {
    await scraper.closeBrowser()
  },
})
```

Databases registered with `registerDatabase()` are disconnected automatically after requests have drained. Do not also call `disconnect()` on them in a hook. Each hook has a time limit (half the shutdown timeout, at least 1 second), so a hook that hangs cannot block the process from exiting.
