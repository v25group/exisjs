# Middleware

ExisJS comes with a collection of built-in middleware out of the box.

ExisJS provides first-party implementations for features like CORS, Request Logging, Backpressure, In-Memory Rate Limiting, Idempotency, and Deduplication.

All middleware can be imported directly from the `exisjs/middleware` package.

---

## Where to Apply Middleware

ExisJS gives you granular control over where your middleware executes:

1. **Globally (`server.ts`)**: Applies to every request hitting your server via `app.use()`.
2. **Folder-Scoped (`boundary.ts`)**: Applies to routes inside that folder and all subfolders automatically.
3. **Route-Scoped (`route.ts`)**: Applies only to a specific endpoint.

```typescript filename="src/http/admin/boundary.ts"
import { defineBoundary } from 'exisjs/router'
import type { Request, Response, Next } from 'exisjs/router'
import { requestLogger } from 'exisjs/middleware'

export const config = defineBoundary({})

// Auto-detected chain step for /admin/*
export const logger = requestLogger({ level: 'debug' })
```

### Middleware Context Type Inference (`defineMiddleware`)

When custom middlewares attach data to `req` (such as authenticated user details, session data, or tenant tokens), ExisJS supports **End-to-End Middleware Context Type Inference**.

By using `defineMiddleware<TContext>()`, downstream route handlers automatically inherit strongly typed properties on `req` with zero manual type casts (`as any`) or boilerplate.

#### Local Route-Level Inference (Recommended)

```typescript filename="src/http/route.ts"
import { controller, route, defineMiddleware } from 'exisjs/router'

// 1. Define your custom context shape
interface AuthContext {
  user: {
    id: string
    role: 'admin' | 'user'
    email: string
  }
}

// 2. Define the middleware with your context
export const authMiddleware = defineMiddleware<AuthContext>((req, res, next) => {
  req.user = {
    id: 'usr_123',
    role: 'admin',
    email: 'alex@example.com'
  }
  next()
})

export default controller({
  profile: route.get('/profile', {
    middlewares: [authMiddleware],
    handle({ req, res }) {
      // ✨ req.user is automatically inferred directly from middlewares: [authMiddleware]!
      // Full autocomplete and strict type safety:
      return res.json({
        userId: req.user.id,
        role: req.user.role,
        email: req.user.email
      })
    }
  })
})
```

#### Multi-Middleware Context Composition

When passing multiple middlewares, ExisJS automatically merges all injected contexts:

```typescript
const authMw = defineMiddleware<{ user: { id: string } }>(...)
const tenantMw = defineMiddleware<{ tenantId: string }>(...)

export default controller({
  data: route.get('/data', {
    middlewares: [authMw, tenantMw],
    handle({ req }) {
      // req has both `req.user` and `req.tenantId` strictly typed!
      return { userId: req.user.id, tenant: req.tenantId }
    }
  })
})
```

#### Module-Scoped Context (`createRouter<TContext>()`)

If an entire file or subsystem shares the same context, use `createRouter<TContext>()`:

```typescript filename="src/http/admin/route.ts"
import { createRouter } from 'exisjs/router'

interface AdminContext {
  user: { id: string; role: 'admin' }
}

const { route, controller } = createRouter<AdminContext>()

export default controller({
  settings: route.get('/settings', {
    middlewares: [authMiddleware],
    handle({ req }) {
      return { adminId: req.user.id }
    }
  })
})
```

#### Boundary-Scoped Context (`defineBoundary<TContext>()`)

Propagate context types across all routes in a directory tree:

```typescript filename="src/http/admin/boundary.ts"
import { defineBoundary } from 'exisjs/router'

export const config = defineBoundary<AdminContext>({
  beforeHandle: async ({ req }) => {
    console.log(`Admin action by: ${req.user.id}`)
  }
})
```

#### Class-Based (OOP) Context Usage

In OOP controllers, you can attach typed middlewares via `@Use()` and type the injected `@Req()` object:

```typescript filename="src/http/admin/route.ts"
import { Controller, Get, Use, Req } from 'exisjs/decorators'
import type { Request } from 'exisjs/router'
import { authMiddleware } from '../../middleware/auth'
import type { AuthContext } from '../../middleware/auth'

@Controller('/admin')
@Use(authMiddleware)
export default class AdminController {
  @Get('/profile')
  getProfile(@Req() req: Request & AuthContext) {
    return {
      userId: req.user.id,
      role: req.user.role,
      email: req.user.email,
    }
  }
}
```

#### Functional Paradigm

```typescript filename="src/http/route.ts"
import { controller, route } from 'exisjs/router'
import { validate } from 'exisjs/middleware'
import { tex } from 'exisjs/validator'

const mySchema = {
  body: tex.object({ name: tex.string() })
}

export default controller({
  create: route.post('/', {
    middlewares: [validate(mySchema)],
    handle({ req }) {
      return { ok: true, name: req.body.name }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Post, Use } from 'exisjs/decorators'
import { validate } from 'exisjs/middleware'
import { tex } from 'exisjs/validator'

const mySchema = {
  body: tex.object({ name: tex.string() })
}

@Controller()
export default class MyController {
  @Use(validate(mySchema))
  @Post('/')
  async create() {
    return { ok: true }
  }
}
```

## 1. CORS

The `cors` middleware handles Cross-Origin Resource Sharing.

The recommended practice in ExisJS is to configure CORS globally in your **`exis.config.ts`** file or per-folder in `boundary.ts`.

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default async () => defineConfig({
  cors: {
    origin: ['https://myapp.com', /localhost:\d+/],
    methods: ['GET', 'POST', 'OPTIONS'],
    credentials: true,
    maxAge: 86400,
  }
})
```

## 2. Request Logger

ExisJS uses Pino under the hood. The `requestLogger` injects a request-scoped logger instance (`req.log`) and times response cycles automatically.

```typescript filename="src/http/server.ts"
import { requestLogger } from 'exisjs/middleware'

app.use(requestLogger({
  level: 'debug',
  pretty: true
}))
```

## 3. Request ID

Injects a unique `X-Request-Id` into every incoming request and outgoing response header. Supports distributed tracing headers (`traceparent`, `x-b3-traceid`).

```typescript filename="src/http/server.ts"
import { requestId } from 'exisjs/middleware'

app.use(requestId())
```

## 4. Rate Limiting (In-Memory / Native Off-Heap)

ExisJS provides high-performance rate limiting powered by Rust native memory:

#### Functional Paradigm

```typescript filename="src/http/auth/route.ts"
import { controller, route } from 'exisjs/router'
import { rateLimit } from 'exisjs/middleware'

const authLimiter = rateLimit({ windowMs: 60000, max: 10 })

export default controller({
  login: route.post('/login', {
    middlewares: [authLimiter],
    handle({ req }) {
      return { status: 'ok' }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/auth/route.ts"
import { Controller, Post, Use } from 'exisjs/decorators'
import { rateLimit } from 'exisjs/middleware'

const authLimiter = rateLimit({ windowMs: 60000, max: 10 })

@Controller('/auth')
export default class AuthController {
  @Post('/login')
  @Use(authLimiter)
  async login() {
    return { status: 'ok' }
  }
}
```

> [!NOTE]
> Core rate limiting runs completely off-heap in-memory. For Redis-backed distributed rate limiting across clusters, use `@exisjs/cache`.

## 5. Idempotency (In-Memory / Native Off-Heap)

Idempotency caches responses based on the `Idempotency-Key` header, preventing duplicate mutations:

#### Functional Paradigm

```typescript filename="src/http/checkout/route.ts"
import { controller, route } from 'exisjs/router'
import { idempotent } from 'exisjs/middleware'

export default controller({
  checkout: route.post('/', {
    middlewares: [idempotent({ ttlMs: 86400000 })],
    async handle() {
      return { success: true }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/checkout/route.ts"
import { Controller, Post, Idempotent } from 'exisjs/decorators'

@Controller('/checkout')
export default class CheckoutController {
  @Idempotent({ ttlMs: 86400000 })
  @Post('/')
  async checkout() {
    return { success: true }
  }
}
```

## 6. Request Deduplication (`dedupe`)

If multiple clients request the exact same resource concurrently, `dedupe` collapses identical in-flight requests into a single operation:

#### Functional Paradigm

```typescript filename="src/http/stats/route.ts"
import { controller, route } from 'exisjs/router'
import { dedupe } from 'exisjs/middleware'

export default controller({
  getStats: route.get('/', {
    middlewares: [dedupe({ ttlMs: 5000 })],
    async handle() {
      return { activeUsers: 1000 }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/stats/route.ts"
import { Controller, Get, Use } from 'exisjs/decorators'
import { dedupe } from 'exisjs/middleware'

@Controller('/stats')
export default class StatsController {
  @Get('/')
  @Use(dedupe({ ttlMs: 5000 }))
  async getStats() {
    return { activeUsers: 1000 }
  }
}
```

## 9. Request Timeout (`timeout`)

The `timeout()` middleware terminates runaway requests and returns `503 Service Unavailable` (or a custom status code).

ExisJS defaults to **60 seconds (60000ms)** to provide generous headroom for slow network connections and third-party cloud operations (Cloudinary, AWS S3, OpenAI, Stripe).

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { timeout } from 'exisjs/middleware'

export default exis({
  async onStart(app) {
    app.use(timeout({
      ms: 60000,
      statusCode: 504,
      message: 'Gateway Timeout connecting to upstream cloud service',
      // Bypass webhooks or long-lived streaming endpoints
      exclude: ['/webhooks/*', '/ai/stream'],
    }))
  }
})
```

Handlers can also dynamically adjust timeouts using `req.setTimeout(ms)` and `req.clearTimeout()`.

### Route-Level Timeout Overrides

Long-running routes (file uploads, PDF exports, AI inferences, data migrations) can declare custom timeouts directly in the route definition, overriding any global application timeout:

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  heavyTask: route.post('/heavy-task', {
    timeoutMs: 120000, // 2 minutes for this endpoint only
    async handle({ body }) {
      return await generateLargeReport(body)
    }
  }),

  exportStream: route.get('/export', {
    timeoutMs: 0, // 0 disables timeout completely for infinite SSE / streaming
    async handle({ res }) {
      return streamDataToClient(res)
    }
  })
})
```

#### Class-Based (OOP) Paradigm

Use the `@Timeout(ms)` decorator on any controller method:

```typescript filename="src/http/ai/controller.ts"
import { Controller, Post, Timeout } from 'exisjs/decorators'

@Controller('/ai')
export default class AiController {
  @Post('/inference')
  @Timeout(120000)
  async runInference() {
    return await computeModel()
  }
}
```

### Declarative Route Uploads

You can configure file uploads directly within functional route declarations:

```typescript filename="src/http/media/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  upload: route.post('/photo', {
    upload: {
      field: 'file',
      maxSize: '10MB',
      allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
      destination: 'memory', // 'memory' | 'disk' | 'stream'
    },
    async handle({ file, fields, req }) {
      // file.buffer, file.mimetype, file.filename are immediately accessible
      return { success: true, filename: file.filename }
    }
  })
})
```

### Class-Based (OOP) Upload Decorators

Use `@UseUpload` or `@Upload` to configure file parsing on controller actions:

```typescript filename="src/http/media/controller.ts"
import { Controller, Post, UseUpload, UploadedFile, Body } from 'exisjs/decorators'

@Controller('/media')
export default class MediaController {
  @Post('/photo')
  @UseUpload({
    field: 'file',
    maxSize: '10MB',
    allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    destination: 'memory',
  })
  async uploadPhoto(@UploadedFile() file: any, @Body() fields: any) {
    return { filename: file.filename, size: file.size }
  }
}
```

### Express / Connect Multer Bridge (`fromExpress`)

Seamlessly run existing Express/Connect middleware such as **Multer** directly in ExisJS without manual Promise wrapping:

```typescript filename="src/http/legacy/route.ts"
import { controller, route } from 'exisjs/router'
import { fromExpress } from 'exisjs/middleware'
import multer from 'multer'

const upload = multer({ storage: multer.memoryStorage() })

export default controller({
  upload: route.post('/', 
    fromExpress(upload.single('file')),
    ({ req }) => {
      const file = (req.raw as any).file || req.file
      return { success: true, originalname: file?.originalname }
    }
  )
})
```

## 10. Security Scanner Noise Suppression & Blackhole (`blockSuspiciousProbes`)

In public production deployments, automated vulnerability scanners aggressively probe for `.env`, `/.git/HEAD`, `/.env.backup`, `/.DS_Store`, `wp-config.php`, etc.

Each probe generates a `404` error log with structured JSON logging (`{"level":40,"statusCode":404}`), flooding log aggregators and triggering false security alerts.

ExisJS provides `blockSuspiciousProbes` (alias `blockProbes`) to immediately intercept known exploit patterns, terminate the request with an empty response (blackhole), and suppress logger noise.

### Global Usage (`server.ts` / `exis.config.ts`)

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { blockSuspiciousProbes } from 'exisjs/middleware'

export default exis({
  async onStart(app) {
    // Intercept probes before downstream routes or loggers
    app.use(blockSuspiciousProbes({
      statusCode: 404, // or 403
      silent: true,    // Suppresses level-40 warning logs in requestLogger
    }))
  }
})
```

Or enable directly in `exis.config.ts`:

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default async () => defineConfig({
  blockProbes: true, // or { statusCode: 404, silent: true }
})
```

### Folder-Scoped Boundary (`boundary.ts`)

```typescript filename="src/http/boundary.ts"
import { defineBoundary } from 'exisjs/router'

export default defineBoundary({
  blockProbes: {
    statusCode: 404,
    silent: true,
    exclude: ['/.well-known/security.txt'],
  }
})
```

### Class-Based (OOP) Decorator

```typescript filename="src/http/api/route.ts"
import { Controller, Get, BlockProbes } from 'exisjs/decorators'

@Controller('/api')
@BlockProbes({ statusCode: 404 })
export default class ApiController {
  @Get('/health')
  health() {
    return { status: 'healthy' }
  }
}
```

### Configuration Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `statusCode` | `number` | `404` | HTTP status code to return for blocked probes |
| `blackhole` | `boolean` | `true` | Immediately terminates connection with empty body without calling downstream middleware |
| `silent` | `boolean` | `true` | Suppresses `requestLogger` warning logs for blocked probe requests |
| `patterns` | `(string \| RegExp)[]` | `[]` | Additional custom probe patterns to block |
| `exclude` | `(string \| RegExp)[]` | `[]` | Whitelist patterns to allow through without blocking |
| `onProbe` | `(req, res, pattern) => void` | `undefined` | Callback hook when a probe is detected (for SIEM or IP reputation metrics) |
