# Middleware

ExisJS comes with a collection of built-in middleware out of the box.

ExisJS provides first-party implementations for features like CORS, Request Logging, Backpressure, In-Memory Rate Limiting, Idempotency, and Deduplication.

All middleware can be imported directly from the `exisjs/middleware` package.

---

## Where to Apply Middleware

ExisJS gives you granular control over where your middleware executes:

1. **Globally (`server.ts`)**: Applies to every request hitting your server via `app.use()`.
2. **Folder-Scoped (`boundary.ts`)**: Applies to routes inside that folder and all subfolders automatically.
3. **Route-Scoped (`route.ts`)**: Applies only to a specific endpoint.

```typescript filename="src/http/admin/boundary.ts"
import { defineBoundary } from 'exisjs/router'
import type { Request, Response, Next } from 'exisjs/router'
import { requestLogger } from 'exisjs/middleware'

export const config = defineBoundary({})

// Auto-detected chain step for /admin/*
export const logger = requestLogger({ level: 'debug' })
```

### Middleware vs Inline Execution

Middleware executes **before** your route handler. If you are using custom typed contexts to destructure variables (e.g., `async handle({ user })`), you must use middleware to populate `req.user`.

#### Functional Paradigm

```typescript filename="src/http/route.ts"
import { controller, route } from 'exisjs/router'
import { validate } from 'exisjs/middleware'
import { tex } from 'exisjs/validator'

const mySchema = {
  body: tex.object({ name: tex.string() })
}

export default controller({
  create: route.post('/', {
    middlewares: [validate(mySchema)],
    handle({ req }) {
      return { ok: true, name: req.body.name }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Post, Use } from 'exisjs/decorators'
import { validate } from 'exisjs/middleware'
import { tex } from 'exisjs/validator'

const mySchema = {
  body: tex.object({ name: tex.string() })
}

@Controller()
export default class MyController {
  @Use(validate(mySchema))
  @Post('/')
  async create() {
    return { ok: true }
  }
}
```

## 1. CORS

The `cors` middleware handles Cross-Origin Resource Sharing.

The recommended practice in ExisJS is to configure CORS globally in your **`exis.config.ts`** file or per-folder in `boundary.ts`.

```typescript filename="exis.config.ts"
import { defineConfig } from 'exisjs/config'

export default async () => defineConfig({
  cors: {
    origin: ['https://myapp.com', /localhost:\d+/],
    methods: ['GET', 'POST', 'OPTIONS'],
    credentials: true,
    maxAge: 86400,
  }
})
```

## 2. Request Logger

ExisJS uses Pino under the hood. The `requestLogger` injects a request-scoped logger instance (`req.log`) and times response cycles automatically.

```typescript filename="src/http/server.ts"
import { requestLogger } from 'exisjs/middleware'

app.use(requestLogger({
  level: 'debug',
  pretty: true
}))
```

---

## 3. Request ID

Injects a unique `X-Request-Id` into every incoming request and outgoing response header. Supports distributed tracing headers (`traceparent`, `x-b3-traceid`).

```typescript filename="src/http/server.ts"
import { requestId } from 'exisjs/middleware'

app.use(requestId())
```

---

## 4. Rate Limiting (In-Memory / Native Off-Heap)

ExisJS provides high-performance rate limiting powered by Rust native memory:

```typescript filename="src/http/boundary.ts"
import { rateLimit } from 'exisjs/middleware'

export const limiter = rateLimit({
  windowMs: 60000,
  max: 100,
})
```

> [!NOTE]
> Core rate limiting runs completely off-heap in-memory. For Redis-backed distributed rate limiting across clusters, use `@exisjs/cache`.

---

## 5. Idempotency (In-Memory / Native Off-Heap)

Idempotency caches responses based on the `Idempotency-Key` header, preventing duplicate mutations:

```typescript filename="src/http/checkout/route.ts"
import { Controller, Post, Idempotent } from 'exisjs/decorators'

@Controller('/checkout')
export default class CheckoutController {
  @Idempotent({ ttlMs: 86400000 })
  @Post('/')
  async checkout() {
    return { success: true }
  }
}
```

---

## 6. Request Deduplication (`dedupe`)

If multiple clients request the exact same resource concurrently, `dedupe` collapses identical in-flight requests into a single operation:

```typescript filename="src/http/stats/route.ts"
import { controller, route } from 'exisjs/router'
import { dedupe } from 'exisjs/middleware'

export default controller({
  getStats: route.get('/', {
    middlewares: [dedupe({ ttlMs: 5000 })],
    async handle() {
      return { activeUsers: 1000 }
    }
  })
})
```

---

## 7. Static File Serving

A static file server that resolves MIME types and streams files:

```typescript
import { serveStatic } from 'exisjs/middleware'
import path from 'node:path'

app.use('/public', serveStatic(path.join(process.cwd(), 'public'), {
  maxAge: 31536000
}))
```

## 8. Compression (Gzip / Brotli / Deflate)

Stream-based compression middleware supporting Gzip, Deflate, and Brotli:

```typescript filename="exis.config.ts"
import type { ExisConfig } from 'exisjs/config'

const config: ExisConfig = {
  compression: true,
}

export default config
```

## 9. Request Timeout (`timeout`)

The `timeout()` middleware terminates runaway requests and returns `503 Service Unavailable` (or a custom status code).

ExisJS defaults to **60 seconds (60000ms)** to provide generous headroom for slow network connections and third-party cloud operations (Cloudinary, AWS S3, OpenAI, Stripe).

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { timeout } from 'exisjs/middleware'

export default exis({
  async onStart(app) {
    app.use(timeout({
      ms: 60000,
      statusCode: 504,
      message: 'Gateway Timeout connecting to upstream cloud service',
      // Bypass webhooks or long-lived streaming endpoints
      exclude: ['/webhooks/*', '/ai/stream'],
    }))
  }
})
```

Handlers can also dynamically adjust timeouts using `req.setTimeout(ms)` and `req.clearTimeout()`.

### Route-Level Timeout Overrides

Long-running routes (file uploads, PDF exports, AI inferences, data migrations) can declare custom timeouts directly in the route definition, overriding any global application timeout:

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  heavyTask: route.post('/heavy-task', {
    timeoutMs: 120000, // 2 minutes for this endpoint only
    async handle({ body }) {
      return await generateLargeReport(body)
    }
  }),

  exportStream: route.get('/export', {
    timeoutMs: 0, // 0 disables timeout completely for infinite SSE / streaming
    async handle({ res }) {
      return streamDataToClient(res)
    }
  })
})
```

#### Class-Based (OOP) Paradigm

Use the `@Timeout(ms)` decorator on any controller method:

```typescript filename="src/http/ai/controller.ts"
import { Controller, Post, Timeout } from 'exisjs/decorators'

@Controller('/ai')
export default class AiController {
  @Post('/inference')
  @Timeout(120000)
  async runInference() {
    return await computeModel()
  }
}
```

### Declarative Route Uploads

You can configure file uploads directly within functional route declarations:

```typescript filename="src/http/media/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  upload: route.post('/photo', {
    upload: {
      field: 'file',
      maxSize: '10MB',
      allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
      destination: 'memory', // 'memory' | 'disk' | 'stream'
    },
    async handle({ file, fields, req }) {
      // file.buffer, file.mimetype, file.filename are immediately accessible
      return { success: true, filename: file.filename }
    }
  })
})
```

### Class-Based (OOP) Upload Decorators

Use `@UseUpload` or `@Upload` to configure file parsing on controller actions:

```typescript filename="src/http/media/controller.ts"
import { Controller, Post, UseUpload, UploadedFile, Body } from 'exisjs/decorators'

@Controller('/media')
export default class MediaController {
  @Post('/photo')
  @UseUpload({
    field: 'file',
    maxSize: '10MB',
    allowedMimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    destination: 'memory',
  })
  async uploadPhoto(@UploadedFile() file: any, @Body() fields: any) {
    return { filename: file.filename, size: file.size }
  }
}
```

### Express / Connect Multer Bridge (`fromExpress`)

Seamlessly run existing Express/Connect middleware such as **Multer** directly in ExisJS without manual Promise wrapping:

```typescript filename="src/http/legacy/route.ts"
import { controller, route } from 'exisjs/router'
import { fromExpress } from 'exisjs/middleware'
import multer from 'multer'

const upload = multer({ storage: multer.memoryStorage() })

export default controller({
  upload: route.post('/', 
    fromExpress(upload.single('file')),
    ({ req }) => {
      const file = (req.raw as any).file || req.file
      return { success: true, originalname: file?.originalname }
    }
  )
})
```
