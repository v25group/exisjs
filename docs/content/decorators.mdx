# Decorators

ExisJS provides standard ECMAScript decorators for developers who prefer the Object-Oriented Programming (OOP) paradigm.

Because ExisJS does not rely on reflection libraries like `reflect-metadata`, these decorators are fast, lightweight, and memory-efficient.

All decorators can be imported directly from `exisjs/decorators`.

---

## 1. Application & Boundary Decorators

ExisJS allows you to configure your root application and directory-scoped boundaries using decorators.

### `@Server(config)`
Used in your entry point (e.g. `src/http/server.ts`) to configure plugins and root providers in an OOP style:

```typescript filename="src/http/server.ts"
import { Server } from 'exisjs/decorators'
import type { App } from 'exisjs'

@Server({
  providers: [['Logger', { useValue: console }]]
})
export default class RootServer {
  async onStart(app: App) {
    console.log('Server started')
  }
}
```

### `@Boundary(config)`
Used inside any folder (e.g. `src/http/admin/boundary.ts`) to configure folder-scoped CORS, headers, exclusions, and DI providers:

```typescript filename="src/http/admin/boundary.ts"
import { Boundary } from 'exisjs/decorators'
import type { Request, Response, Next, BoundaryContext } from 'exisjs/router'
import { UnauthorizedError } from 'exisjs/error'

@Boundary({
  cors: { origin: 'https://admin.yourdomain.com', credentials: true },
  headers: { 'X-Admin-Api-Version': '2.0' },
  exclude: ['/admin/health'],
})
export default class AdminBoundary {
  // Chain step auto-detected by (req, res, next) signature
  requireAuth(req: Request, res: Response, next: Next) {
    if (!req.headers['x-api-key']) {
      throw new UnauthorizedError('Missing API key')
    }
    next()
  }

  // Request wrapper auto-detected by handle(ctx, next)
  async handle(ctx: BoundaryContext, next: Next) {
    const start = Date.now()
    const result = await next()
    ctx.res.setHeader('X-Response-Time', `${Date.now() - start}ms`)
    return result
  }
}
```

## 2. Controllers & Routing

To map a class to a route prefix, use the `@Controller()` decorator. HTTP method decorators then map class methods to specific endpoints.

```typescript filename="src/http/users/route.ts"
import { Controller, Get, Post, Put, Patch, Delete } from 'exisjs/decorators'
import { UserParamsSchema, CreateUserSchema } from './schema'

@Controller('/users')
export default class UsersController {
  @Get('/')
  async listUsers() {
    return { users: [] }
  }

  @Get('/:id', UserParamsSchema)
  async getUser() {
    return { id: 1 }
  }

  @Post('/', CreateUserSchema)
  async createUser() {
    return { success: true }
  }

  @Delete('/:id')
  async deleteUser() {}
}
```

### Available Method Decorators
- `@Get(path?, schema?)`
- `@Post(path?, schema?)`
- `@Put(path?, schema?)`
- `@Patch(path?, schema?)`
- `@Delete(path?, schema?)`
- `@Options(path?, schema?)`
- `@Head(path?, schema?)`
- `@Connect(path?, schema?)`
- `@Trace(path?, schema?)`
- `@All(path?, schema?)`

## 3. Request Parameters

Parameter decorators extract request properties and inject them directly into your method parameters:

```typescript filename="src/http/users/route.ts"
import { Controller, Post, Body, Param, Headers, Req, Res } from 'exisjs/decorators'

@Controller('/users')
export default class UsersController {
  @Post('/:id')
  async update(
    @Param('id') id: string,
    @Body() payload: any,
    @Headers('authorization') token: string,
    @Req() req: any,
    @Res() res: any
  ) {
    return { success: true, id, payload }
  }
}
```

### Available Parameter Decorators
- `@Body(nameOrPipe?)` — Extracts `req.body` or runs through a validation schema/pipe.
- `@Param(nameOrPipe?)` — Extracts a route path param (e.g. `:id`).
- `@QueryParam(nameOrPipe?)` / `@Query(nameOrPipe?)` — Extracts a query parameter from the URL query string.
- `@Headers(nameOrPipe?)` — Extracts a request header by name.
- `@Cookies(nameOrPipe?)` / `@Cookie(nameOrPipe?)` — Injects incoming parsed cookies or a specific cookie value.
- `@State(keyOrPipe?)` — Injects request state from execution context or middleware.
- `@AppCtx()` — Injects the root ExisJS Application instance.
- `@Fields(nameOrPipe?)` — Injects non-file multipart form fields.
- `@UploadedFile(nameOrPipe?)` — Injects a single uploaded file.
- `@UploadedFiles(nameOrPipe?)` — Injects multiple uploaded files.
- `@HostParam(nameOrPipe?)` — Extracts a host subdomain parameter.
- `@Req()` — Injects the raw request object.
- `@Res(options?)` — Injects the response object (e.g. `{ passthrough: true }`).
- `@Ip()` — Injects the client IP address.
- `@Next()` — Injects the `next` function.
- `createParamDecorator(factory)` — Creates custom reusable route parameter decorators:
  ```typescript
  export const CurrentUser = createParamDecorator((data: string | undefined, ctx) => {
    return data ? ctx.req.user?.[data] : ctx.req.user
  })
  ```

## 4. Middleware & Pipeline Decorators

You can bind middlewares, guards, interceptors, and exception filters to controllers or route methods using first-class decorators:

```typescript filename="src/http/checkout/route.ts"
import { Controller, Post, Use, Idempotent, RateLimit, Cors, Timeout } from 'exisjs/decorators'
import { requireAuth } from '../../middleware/auth'

@Controller('/checkout')
@Use(requireAuth) // Applies to all routes in this controller
@Cors({ origin: 'https://app.yourdomain.com' })
@RateLimit({ max: 10, windowMs: 60000 })
export default class CheckoutController {
  @Post('/')
  @Timeout(30000)
  @Idempotent({ ttlMs: 86400000 }) // In-memory off-heap idempotency protection
  async processPayment() {
    return { success: true }
  }
}
```

### Available Lifecycle & Middleware Decorators
- `@Use(...items)` — Unified decorator that attaches middlewares, guards (`canActivate`), interceptors (`intercept`), or exception filters (`catch`) to a class or method.
- `@UseGuards(...guards)` — Explicit alias for `@Use` dedicated to route guards.
- `@UseInterceptors(...interceptors)` — Explicit alias for `@Use` dedicated to interceptors.
- `@UseFilters(...filters)` — Explicit alias for `@Use` dedicated to exception filters.
- `@Catch(...exceptions)` — Declares exception classes handled by an Exception Filter.
- `@Timeout(ms: number | TimeoutOptions)` — Overrides the request timeout for a class or method.
- `@Idempotent(options?)` — Caches responses based on the `Idempotency-Key` header using native in-memory off-heap storage.
- `@RateLimit(options?)` — Enforces request rate limits on a controller class or route method.
- `@Cors(options?)` — Configures Cross-Origin Resource Sharing rules on a controller class or route method.
- `@IpFilter(options)` — Enforces IP/CIDR allowlist and denylist.
- `@Compress()` — Enables automatic response compression (Gzip/Brotli).
- `@Dedupe(options)` — Deduplicates concurrent identical requests sharing the same key.
- `@UseUpload(options)` / `@Upload(options)` — Configures multipart file upload handling.
- `@BlockProbes(options?)` — Intercepts scanner exploit probes (`.env`, `/.git`, `/.DS_Store`) and blackholes them without log noise.

## 5. Security & Authorization Decorators

Declare access control rules directly on controller classes and route methods:

```typescript filename="src/http/roles/route.ts"
import { Controller, Get, Post, Body, Use, Permissions, Roles, Public } from 'exisjs/decorators'
import { AuthGuard } from '@/common/guards/auth.guard'

@Controller('/roles')
@Use(AuthGuard) // Enforced on all routes in this controller
export default class RolesController {
  @Get('/public')
  @Public() // Bypasses auth guard for public inspection
  async getPublicInfo() {
    return { status: 'public' }
  }

  @Get('/')
  @Roles('admin', 'manager') // Requires user to have admin or manager role
  async getRoles() {
    return { roles: [] }
  }

  @Post('/')
  @Permissions('role:create', 'role:manage') // Granular permission check
  async createRole(@Body() body: any) {
    return { success: true }
  }
}
```

### Available Security Decorators
- `@Permissions(...permissions: string[])` — Declares required permissions (auto-bypassed when `req.user.isSuperAdmin` is true).
- `@Roles(...roles: string[])` — Declares required role names.
- `@Public()` / `@IsPublic()` / `@AllowAnonymous()` — Marks an endpoint or controller as public, instructing global auth guards to skip credential verification.

## 6. Service Enhancements: Caching, Transactions & Profiling

ExisJS provides high-performance method decorators for `@Injectable()` services:

```typescript filename="src/http/orders/service.ts"
import { Injectable, Cacheable, CacheEvict, Transactional, Profile, type OnInit, type OnDestroy } from 'exisjs/decorators'

@Injectable()
export class OrderService implements OnInit, OnDestroy {
  async onInit() {
    console.log('OrderService initialized')
  }

  async onDestroy() {
    console.log('OrderService destroyed')
  }

  // Caches result in off-heap Rust cache for 300 seconds
  @Cacheable({ ttl: 300, key: (id: string) => `order:${id}` })
  @Profile({ thresholdMs: 50, warnSlow: true })
  async getOrder(id: string) {
    return this.db.query('SELECT * FROM orders WHERE id = $1', [id])
  }

  // Automatically runs in a database transaction and evicts cached entries
  @Transactional()
  @CacheEvict({ key: (id: string) => `order:${id}` })
  async updateOrder(id: string, data: any) {
    return this.db.update('orders', id, data)
  }
}
```

### Available Service Decorators & Lifecycle Interfaces
- `@Cacheable({ ttl?: number, key?: string | ((...args) => string) })` — Caches method return values in off-heap memory.
- `@CacheEvict({ key: string | ((...args) => string) })` — Evicts cached keys on mutation.
- `@Transactional(options?)` — Wraps service operations in an atomic database transaction.
- `@Profile({ thresholdMs?: number, warnSlow?: boolean, log?: Function })` — Measures method execution time with sub-millisecond precision.
- `OnInit` (`onInit()`) & `OnDestroy` (`onDestroy()`) — Service startup and shutdown lifecycle hooks.
- `OnModuleInit`, `OnModuleDestroy`, `OnApplicationBootstrap` — Module lifecycle hooks.

## 7. Response & Metadata Modifiers

Modify HTTP response status codes, redirect clients, or set headers declaratively:

```typescript filename="src/http/api/route.ts"
import { Controller, Post, Get, HttpCode, Header, Redirect, SetMetadata, Reflector } from 'exisjs/decorators'

@Controller('/api')
@SetMetadata('roles', ['admin'])
export default class ApiController {
  @Post('/create')
  @HttpCode(201) // Forces 201 Created
  @Header('X-Custom-Version', '2.0')
  @SetMetadata('permissions', ['write:api'])
  async create() {
    return { success: true }
  }

  @Get('/legacy')
  @Redirect('/new-api', 301)
  async legacy() {}
}
```

### Available Response & Metadata Decorators
- `@HttpCode(code: number)` — Sets the response HTTP status code.
- `@Header(name: string, value: string)` — Injects a response header.
- `@Returns(schema)` — Attaches response schema for OpenAPI/Swagger generation.
- `@Redirect(url: string, statusCode?: number)` — Redirects the client.
- `@Hosts(...hosts: string[])` — Restricts route/controller to specific Host headers.
- `@SetMetadata(key, value)` — Attaches custom metadata to a class or method.
- `Reflector` — Static utility to inspect metadata attached via `@SetMetadata` across classes and methods.

## 8. Dependency Injection & Modules

To mark a service class as an injectable provider for the IoC container, use the `@Injectable()` decorator. ExisJS supports `singleton` (default), `request`, and `transient` scopes:

```typescript filename="src/http/users/service.ts"
import { Injectable } from 'exisjs/decorators'

@Injectable({ scope: 'transient' })
export class UserService {
  async fetchUser(id: string) {
    return { id, name: 'Alice' }
  }
}
```

### Constructor Parameter Injection (`@Inject` & `@Optional`)

You can inject dependencies using tokens or classes, and mark optional dependencies with `@Optional()`:

```typescript filename="src/http/users/route.ts"
import { Controller, Get, Param } from 'exisjs/decorators'
import { Inject, Optional } from 'exisjs/di'
import { UserService } from './service'

@Controller('/users')
export default class UsersController {
  constructor(
    private userService: UserService,
    @Inject('DATABASE_URL') private dbUrl: string,
    @Optional() @Inject('ANALYTICS_SERVICE') private analytics?: any
  ) {}

  @Get('/:id')
  async getUser(@Param('id') id: string) {
    return this.userService.fetchUser(id)
  }
}
```

### Application Modules (`@Module`)

You can group controllers, providers, and imports into high-level OOP modules using `@Module`:

```typescript filename="src/http/users/users.module.ts"
import { Module } from 'exisjs/module' // or 'exisjs/decorators'
import UsersController from './route'
import { UserService } from './service'

@Module({
  controllers: [UsersController],
  providers: [UserService],
  exports: [UserService]
})
export class UsersModule {}
```
