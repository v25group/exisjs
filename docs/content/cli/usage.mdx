# CLI Usage

The ExisJS CLI (`exisjs` or `exis`) can be executed through global package managers, on-demand runner utilities like `npx`, or locally defined `package.json` scripts.

---

## Execution Methods

### 1. On-Demand Execution (`npx`)

When initializing a new application or running ad-hoc commands without a global install:

```bash
# Initialize a project in the current working directory
npx exisjs init

# Check environment diagnostics
npx exisjs doctor

# Print the application routing table
npx exisjs routes
```

### 2. Global Installation

For system-wide command availability:

```bash
# Install globally
npm install -g exisjs

# Run directly
exisjs dev
exis routes
```

### 3. Project-Local Scripts (Recommended)

When working inside an established project, invoking the CLI via `npm run` ensures consistent execution pinned to the local `exisjs` dependency in `node_modules`.

---

## Default Package Scripts

Applications initialized with `npx exisjs init` include standard npm lifecycle scripts in `package.json`:

```json
{
  "name": "my-exis-app",
  "version": "1.0.0",
  "scripts": {
    "dev": "exisjs dev",
    "build": "exisjs build",
    "clean": "exisjs clean",
    "start": "exisjs start",
    "test": "exisjs test",
    "routes": "exisjs routes",
    "doctor": "exisjs doctor"
  },
  "dependencies": {
    "exisjs": "^1.0.0"
  },
  "devDependencies": {
    "typescript": "^5.0.0"
  }
}
```

Run these scripts using your preferred package manager:

```bash
# Start development server
npm run dev

# Compile TypeScript and build route manifests
npm run build

# Start production server
npm run start

# Run native test runner
npm test

# Print routing table
npm run routes
```

---

## Passing Arguments to Scripts

When invoking CLI commands through `npm run`, use the double-dash delimiter (`--`) to forward flags and positional arguments to `exisjs`:

```bash
# Run dev server on a custom port
npm run dev -- -p 4000

# Run a specific test file
npm test -- tests/users.test.ts

# Filter routes table by method and path
npm run routes -- -m POST -f /api/v1
```

With `pnpm` or `yarn`:

```bash
# pnpm forwards arguments directly
pnpm dev -p 4000

# yarn forwards arguments directly
yarn dev -p 4000
```

## Environment Configuration

The CLI automatically loads environment variables according to the current execution mode:

| File | Loaded In | Priority |
| :--- | :--- | :--- |
| `.env.local` | All modes (except test) | High |
| `.env.<mode>` | Matching mode (e.g. `.env.production`) | Medium |
| `.env` | All modes | Default |

### Overriding the Environment Mode

Use the `-m, --mode <mode>` flag or set `NODE_ENV`:

```bash
# Build with staging environment variables
npx exisjs build --mode staging

# Execute a script under staging configuration
npx exisjs run scripts/seed.ts --mode staging
```
