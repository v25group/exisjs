# CLI Command Reference

### `exisjs dev`

Starts the development server with live reload and automatic port collision avoidance.

```bash
$ npx exisjs dev [options]
```

**Options**

| Option | Description |
| :--- | :--- |
| `-p, --port <port>` | Port to listen on (overrides `.env` and `exis.config.ts`). |
| `-H, --host <host>` | Host to bind to (e.g. `0.0.0.0` or `localhost`). |
| `-e, --entry <file>` | Custom entry file path (default: `src/http/server.ts`). |

- **Automatic Port Collision Detection**: If the designated port is occupied, the CLI detects the conflict and increments to the next available port automatically.
- **PID Lockfile**: Manages a `.exis/dev.pid` lockfile to prevent accidentally spawning duplicate dev servers in the same directory.

### `exisjs build`

Compiles TypeScript to production JavaScript and produces route manifests.

```bash
$ npx exisjs build [options]
```

**Options**

| Option | Description |
| :--- | :--- |
| `-o, --out-dir <dir>` | Output directory (default: `.exis/server` or `dist`). |
| `--no-clean` | Skip cleaning the output directory before compilation. |

- **Type-Check**: Runs the TypeScript compiler in check-only mode (`noEmit`) to verify strict typing before compiling.
- **Fast Bundling**: Emits JavaScript via esbuild.
- **Route Manifest**: Generates `.exis/routes-manifest.js` to enable O(1) route discovery at runtime without filesystem directory walks.

### `exisjs generate`

Scaffolds framework components and files according to ExisJS core conventions.

```bash
$ npx exisjs generate <type> <name> [options]
$ npx exisjs g <type> <name> [options]
```

**Arguments**

| Argument | Description |
| :--- | :--- |
| `<type>` | The schematic type to generate. |
| `<name>` | The name of the feature / folder. |

**Options**

| Option | Description |
| :--- | :--- |
| `-n, --named` | Names generated files using the feature prefix (e.g. `<name>.route.ts`, `<name>.schema.ts`, `<name>.service.ts`). |
| `--oop` | Generates using Class-Based (OOP) decorators instead of Functional syntax. |

**Supported Schematics**

| Schematic | Alias | Description | Output Path |
| :--- | :--- | :--- | :--- |
| `resource` | | Complete domain slice (`schema.ts`, `service.ts`, `route.ts` or feature-prefixed named files) | `src/http/<name>/` |
| `route` | `r`, `c`, `controller` | HTTP route file | `src/http/<name>/route.ts` |
| `service` | `s` | Injectable service / business logic | `src/http/<name>/service.ts` |
| `schema` | `sc` | Validation schemas powered by `tex` | `src/http/<name>/schema.ts` |
| `boundary` | `b` | Folder-scoped configuration and request pipeline | `src/http/<name>/boundary.ts` |
| `plugin` | `p` | Distributable plugin module | `src/plugins/<name>.ts` |
| `middleware` | `m` | Standalone middleware handler | `src/middleware/<name>.ts` |
| `test` | `t` | Native test suite | `tests/<name>.test.ts` |

### `exisjs routes`

Analyzes and prints the application routing table to the terminal in an interactive, formatted grid with method badges and dynamic parameter highlighting.

```bash
$ npx exisjs routes [options]
```

**Options**

| Option | Description |
| :--- | :--- |
| `-e, --entry <file>` | Custom entry file path to bootstrap the app from (default: `src/http/server.ts`). |
| `-m, --method <method>` | Filter endpoints by HTTP method (e.g. `GET`, `POST`, `PUT`, `DELETE`). |
| `-f, --filter <keyword>` | Filter endpoints matching path, method, or source file keyword. |
| `--json` | Output the parsed routes and middleware metadata directly as structured JSON. |

**Features**
- **Method Badges**: Visually styled badges (`GET`, `POST`, `PUT`, `PATCH`, `DEL`, `ALL`).
- **Parameter Highlighting**: Dynamically distinguishes path parameters (`:id`, `*slug`).
- **Middleware Counting**: Displays total attached middleware / boundary steps.
- **Source Resolution**: Displays relative file source path (e.g. `src/http/users/user.route.ts`).
- **Summary Metrics**: Displays total endpoint counts and method breakdown.

Runs the native Node.js test runner (`node:test`) across the project.

### `exisjs doctor`

Performs an end-to-end diagnostic audit of the local project environment, verifying Node.js version compatibility, native Rust hardware acceleration (`@exisjs/rs`), `tsconfig.json` strictness, entry-point resolution, route naming patterns, and file-system route counts.

```bash
$ npx exisjs doctor
```

**Diagnostic Checks**
- **Runtime**: Validates Node.js engine compatibility (v18+ recommended for N-API and worker thread pools).
- **Native Engine**: Verifies `@exisjs/rs` compiled native binaries are active for hardware-accelerated radix tree traversal, off-heap caching, and native JSON serialization.
- **Project Configuration**: Checks `package.json` root and `tsconfig.json` strict mode.
- **Routes & Pipeline**: Confirms application entry point (`src/http/server.ts`), discovers active route slices, and flags non-standard or orphan file naming conventions.
