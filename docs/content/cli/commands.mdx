# CLI Commands

The ExisJS CLI provides tools for local development, production compilation, scaffolding, testing, database scripting, and environment auditing.

---

## `exisjs dev`

Starts the development server with live file watching, TypeScript transpilation, and automatic port collision avoidance.

```bash
npx exisjs dev [options]
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-p, --port <port>` | `number` | `3000` | Port to listen on (overrides `.env` and `exis.config.ts`). |
| `-H, --host <host>` | `string` | `localhost` | Host address to bind to. |
| `-e, --entry <file>` | `string` | `src/http/server.ts` | Custom entry file path to bootstrap the application. |

### Behavior
- **Port Collision Detection**: If the specified port is in use, the CLI automatically increments to the next open port.
- **PID Lockfile**: Manages `.exis/dev.pid` to prevent duplicate dev server processes in the same workspace.

## `exisjs build`

Compiles the TypeScript application to production JavaScript, performs type-checking, and generates static route manifests.

```bash
npx exisjs build [options]
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-o, --out-dir <dir>` | `string` | `.exis/server` | Output directory for compiled JavaScript assets. |
| `--no-clean` | `boolean` | `false` | Skip cleaning the output directory prior to compilation. |
| `--skip-env-check` | `boolean` | `false` | Skip build-time route and environment validation checks. |
| `--dry-run` | `boolean` | `false` | Compile and bundle without halting on missing environment variables. |
| `-m, --mode <mode>` | `string` | `production` | Environment mode to load (e.g. `production`, `staging`). |

### Build Outputs
- Compiles application source code into the specified `outDir`.
- Emits pre-computed route manifests (`.exis/routes-manifest.js`) for O(1) route discovery at runtime.
- Generates TypeScript environment definitions (`.exis/exis.d.ts`).

## `exisjs clean`

Removes temporary build artifacts, compiled files, and cached manifests.

```bash
npx exisjs clean [options]
npx exisjs cl [options]
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-a, --all` | `boolean` | `false` | In addition to `.exis/`, also remove the `dist/` directory. |

## `exisjs start`

Starts the compiled production server from the build output directory.

```bash
npx exisjs start [options]
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-p, --port <port>` | `number` | `3000` | Port to listen on. |
| `-H, --host <host>` | `string` | `0.0.0.0` | Host address to bind to. |
| `-e, --entry <file>` | `string` | `.exis/server/src/http/server.js` | Custom compiled entry file path. |

## `exisjs generate`

Scaffolds framework components and files according to ExisJS file conventions.

```bash
npx exisjs generate <type> [name] [options]
npx exisjs g <type> [name] [options]
```

### Arguments

| Argument | Description |
| :--- | :--- |
| `<type>` | The schematic type to generate. |
| `[name]` | The name of the feature or folder (required for all types except `error`). |

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-n, --named` | `boolean` | `false` | Names generated files using the feature prefix (e.g. `user.route.ts`, `user.schema.ts`). |
| `--oop` | `boolean` | `false` | Generates using Class-Based (OOP) decorators instead of Functional syntax. |

### Supported Schematics

| Schematic | Alias | Description | Output Location |
| :--- | :--- | :--- | :--- |
| `crud` | `resource` | Generates full 4-file CRUD slice (`schema`, `service`, `route`, `model`). | `src/http/<name>/` & `src/models/` |
| `model` | | Standalone database-agnostic TypeScript entity interface. | `src/models/<Name>.ts` |
| `route` | `r`, `c`, `controller` | HTTP route endpoint definition. | `src/http/<name>/route.ts` |
| `service` | `s` | Injectable service with pagination utilities. | `src/http/<name>/service.ts` |
| `schema` | `sc` | Validation schemas with `tex` validators and pagination DTOs. | `src/http/<name>/schema.ts` |
| `boundary` | `b` | Folder-level boundary middleware configuration. | `src/http/<name>/boundary.ts` |
| `cron` | `job` | Scheduled cron background task. | `src/cron/<name>.ts` |
| `error` | `err` | Global error handler fallback. | `src/http/error.ts` |
| `plugin` | `p` | Reusable ExisJS plugin module. | `src/plugins/<name>.ts` |
| `middleware` | `m` | Standalone middleware handler function. | `src/middleware/<name>.ts` |
| `test` | `t` | Integration test file using `node:test` and `exisjs/testing`. | `tests/<name>.test.ts` |

## `exisjs routes`

Inspects and displays the complete application routing table in formatted tabular output or raw JSON.

```bash
npx exisjs routes [options]
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-e, --entry <file>` | `string` | `src/http/server.ts` | Custom entry file path to discover routes from. |
| `-m, --method <method>` | `string` | None | Filter endpoints by HTTP method (e.g. `GET`, `POST`). |
| `-f, --filter <keyword>` | `string` | None | Filter endpoints by path, method, or source file keyword. |
| `--json` | `boolean` | `false` | Output routes and middleware metadata in JSON format. |

## `exisjs test`

Runs the test suite using the integrated Node.js test runner (`node:test`).

```bash
npx exisjs test [files...] [options]
```

### Arguments & Options

| Argument / Option | Type | Description |
| :--- | :--- | :--- |
| `[files...]` | `string[]` | Specific test files or glob patterns to run. |
| `--watch` | `boolean` | Watch for file changes and re-execute tests automatically. |
| `-u, --update` | `boolean` | Update snapshot assertions. |
| `-e, --entry <file>` | `string` | Custom entry file path to bootstrap before test execution. |

## `exisjs run`

Executes standalone scripts, migration utilities, or third-party CLI tools with ExisJS `.env` files automatically loaded into `process.env`.

```bash
npx exisjs run <scriptOrCmd> [args...] [options]
npx exisjs exec <scriptOrCmd> [args...] [options]
```

### Options

| Option | Type | Description |
| :--- | :--- | :--- |
| `-e, --env <file>` | `string` | Path to a specific environment file to load. |
| `-m, --mode <mode>` | `string` | Environment mode to load (e.g. `production`, `staging`, `development`). |

### Examples

```bash
# Execute a TypeScript seed script
npx exisjs run src/database/seed.ts

# Run an external database CLI with ExisJS environment loaded
npx exisjs run prisma migrate deploy
npx exisjs run drizzle-kit push
```

## `exisjs doctor`

Runs an end-to-end diagnostic audit of the local project environment.

```bash
npx exisjs doctor
```

### Diagnostic Checks
- **Runtime Environment**: Validates Node.js version compatibility (Node.js 20+).
- **Project Structure**: Verifies `package.json`, `tsconfig.json`, and application entry points.
- **Route Integrity**: Audits `src/http/` directory for naming conventions and orphan files.

---

## `exisjs info`

Prints runtime environment details, including ExisJS version, Node.js version, platform, and operating system architecture.

```bash
npx exisjs info
```
