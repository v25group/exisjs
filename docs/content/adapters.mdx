# Adapters & Serverless

ExisJS was engineered from the ground up using modern web standards (Fetch API, Request/Response patterns). Because of this, ExisJS isn't just bound to Node.js—it can run virtually anywhere!

To deploy your ExisJS application to serverless or edge environments, you simply wrap your `app` with the corresponding adapter from `exisjs/adapters`.

Every adapter handles **lazy initialization** automatically—your routes, plugins, and lifecycle hooks (`onStart`) are bootstrapped on the very first incoming request (cold start), so you never have to worry about manual setup in serverless environments.

## Vercel

Vercel provides blazing fast serverless functions. To deploy an ExisJS app to Vercel, create an `api/index.js` entrypoint that wraps your app with the `vercel` adapter.

```javascript filename="api/index.js"
import app from '../src/http/server'
import { vercel } from 'exisjs/adapters'

export default vercel(app)
```

Then configure `vercel.json` to route all traffic to this function and bundle the compiled `.exis` directory:

```json filename="vercel.json"
{
  "version": 2,
  "buildCommand": "npm run build",
  "functions": {
    "api/index.js": {
      "includeFiles": ".exis/**/*"
    }
  },
  "rewrites": [
    { "source": "/(.*)", "destination": "/api/index" }
  ]
}
```

> **Note:** ExisJS compiles your application into the `.exis/` directory during `exisjs build`. The `includeFiles` configuration ensures Vercel bundles these compiled files alongside your serverless function. You also need a `public/` directory (even an empty one with a `.keep` file) to prevent Vercel's missing output directory error.

## AWS Lambda

Deploying an ExisJS API as an AWS Lambda function (behind API Gateway) takes one line of code. The `aws` adapter converts API Gateway events into native Node.js HTTP streams that ExisJS understands.

```typescript filename="src/lambda.ts"
import app from './http/server'
import { aws } from 'exisjs/adapters'

// Export the AWS Lambda handler
export const handler = aws(app)
```

The adapter automatically handles:
- Mapping `httpMethod`, `path`, and `queryStringParameters` from API Gateway events
- Converting headers and request bodies
- Collecting the response stream and returning a properly formatted `APIGatewayResult`
- Base64 encoding for binary responses

## Cloudflare Workers

Because ExisJS avoids bulky Node.js-only legacy dependencies, it works flawlessly on Cloudflare Workers using the Web Standard Fetch API.

```typescript filename="src/worker.ts"
import app from './http/server'
import { cloudflare } from 'exisjs/adapters'

export default cloudflare(app)
```

The adapter returns an object with a `fetch` method that Cloudflare Workers expects. Your `env` and `ctx` (execution context) are automatically passed through to your route handlers.

---

## Netlify

Netlify Edge Functions use the Web Standard Fetch API, making ExisJS a perfect fit.

```typescript filename="netlify/edge-functions/api.ts"
import app from '../../src/http/server'
import { netlify } from 'exisjs/adapters'

export default netlify(app)
```

The adapter wraps your app and passes both the incoming `Request` and Netlify's `Context` object through to ExisJS.

## Deno

Deno natively supports the Web Standard Fetch API, so ExisJS runs on it without any compatibility layers.

```typescript filename="src/main.ts"
import app from './http/server'
import { deno } from 'exisjs/adapters'

Deno.serve({ port: 8000 }, deno(app))
```

---

## Bun

Bun provides a native, high-performance HTTP server. The `bun` adapter ties directly into Bun's `serve` function.

```typescript filename="src/main.ts"
import app from './http/server'
import { bun } from 'exisjs/adapters'

Bun.serve({
  port: 3000,
  ...bun(app)
})
```

---

## Fastly Compute@Edge

Fastly's Compute@Edge platform runs your code at the network edge. The `fastly` adapter integrates with Fastly's event-driven model.

```typescript filename="src/index.ts"
import app from './http/server'
import { fastly } from 'exisjs/adapters'

addEventListener('fetch', fastly(app))
```

## The Fetch Adapter (Building Custom Adapters)

Under the hood, ExisJS provides a universal **Fetch adapter** (`handleFetch`) that bridges the gap between the Web Standard `Request`/`Response` API and ExisJS's internal Node.js-style request pipeline.

Every edge/serverless adapter (Cloudflare, Deno, Bun, Netlify, Fastly) ultimately calls `app.fetch()`, which internally uses `handleFetch` to:

1. **Convert** a Web Standard `Request` into a Node.js-compatible `IncomingMessage` (via `FetchIncomingMessage`)
2. **Route** the request through ExisJS's full middleware and routing pipeline
3. **Collect** the response and convert it back into a Web Standard `Response` (via `FetchServerResponse`)

This means you can create your own custom adapter for **any** runtime that supports the Fetch API:

```typescript filename="src/my-custom-adapter.ts"
import app from './http/server'

// app.fetch() works anywhere that has the Web Standard Request/Response API
const server = createMyCustomServer({
  async handler(request: Request): Promise<Response> {
    return app.fetch(request)
  }
})
```

The `app.fetch()` method accepts an optional `env` and `ctx` parameter, which are passed through to your route handlers—allowing platform-specific features (like Cloudflare's KV bindings or Deno's connection info) to be accessed from within your ExisJS routes.

```typescript
// Signature
app.fetch(request: Request, env?: any, ctx?: any): Promise<Response>
```

This architecture ensures that ExisJS remains **100% portable and vendor-agnostic**. Your application code stays the same—only the deployment wrapper changes.
