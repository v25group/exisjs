# Requests

ExisJS wraps the native Node.js `IncomingMessage` object into an `ExisRequest` instance. It abstracts away the complexities of stream parsing, multipart form processing, and header normalization, giving you a typed interface.

---

## 1. Body, Query, and Params

The most common request properties are automatically parsed and strongly typed (especially when using the [Schema Validation](/docs/middleware#8-schema-validation) middleware).

- **`req.body`**: The parsed body of the request (JSON, URL-encoded, or Multipart).
- **`req.query`**: An object containing the URL query string parameters (e.g., `?id=123`).
- **`req.params`**: An object containing route parameters (e.g., `/:id`).

#### Functional Paradigm

```typescript filename="src/http/route.ts"
export default controller({
  updateUser: route.post('/users/:id', {
    handle(req, res) {
      const id = req.params.id          // "123"
      const force = req.query.force     // "true"
      const payload = req.body          // { email: "alice@exisjs.com" }
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Post, Param, Query, Body } from 'exisjs/decorators'

@Controller()
export default class UsersController {
  @Post('/users/:id')
  async updateUser(
    @Param('id') id: string,
    @Query('force') force: string,
    @Body() payload: any
  ) {
    // Variables are automatically injected
  }
}
```

## 2. On-Demand Parsing

To maximize performance, ExisJS does not parse the request body immediately for every route. If you aren't using the Validation middleware, you can manually trigger parsing on-demand.

#### Functional Paradigm

```typescript
export default controller({
  processData: route.post('/process', {
    async handle(req, res) {
      // Parses application/json
      const data = await req.json<{ key: string }>()
      
      // Parses raw text (text/plain)
      const text = await req.text()
    }
  })
})
```

#### Class-Based (OOP) Paradigm

```typescript filename="src/http/route.ts"
import { Controller, Post, Req } from 'exisjs/decorators'

@Controller()
export default class ProcessController {
  @Post('/process')
  async processData(@Req() req: any) {
    // Parses application/json
    const data = await req.json<{ key: string }>()
    
    // Parses raw text (text/plain)
    const text = await req.text()
  }
}
```

## 3. File Uploads & Multipart Form Data

Handling `multipart/form-data` in Node.js can be difficult. ExisJS provides multiple robust, high-performance approaches:

### A. Declarative Route Uploads (Recommended)

You can declare file upload requirements directly inside your route schema. ExisJS automatically executes the multipart parser, validates MIME types, enforces byte caps, and populates `req.file` or `req.files` along with non-file fields in `req.body`:

```typescript filename="src/http/upload/route.ts"
import { controller, route } from 'exisjs/router'
import { tex } from 'exisjs/validator'

export default controller({
  uploadPhoto: route.post('/', {
    upload: {
      field: 'photo',
      maxBytes: 10 * 1024 * 1024, // 10MB limit
      mimeTypes: ['image/jpeg', 'image/png', 'image/webp'],
    },
    body: tex.object({
      title: tex.string({ min: 1 }),
    }),
    handle({ req }) {
      const file = req.file! // Typed UploadedFile
      console.log(`Uploaded ${file.originalname} (${file.size} bytes)`)

      return {
        success: true,
        filename: file.filename,
        mimetype: file.mimetype,
        title: req.body.title,
      }
    }
  })
})
```

### B. First-Party `fileUpload` Middleware

ExisJS exports a dedicated `fileUpload` middleware from `exisjs/middleware` supporting single, multiple, and multi-field uploads:

```typescript filename="src/http/documents/route.ts"
import { controller, route } from 'exisjs/router'
import { fileUpload } from 'exisjs/middleware'

export default controller({
  // Single file upload
  single: route.post('/single', 
    fileUpload.single('document', {
      maxBytes: 15 * 1024 * 1024, // 15MB
      dest: './uploads/docs',
    }),
    ({ req }) => {
      return { file: req.file }
    }
  ),

  // Multiple files with the same field name
  gallery: route.post('/gallery',
    fileUpload.array('photos', 5, {
      mimeTypes: ['image/*'],
    }),
    ({ req }) => {
      const files = req.files // UploadedFile[]
      return { count: files?.length }
    }
  ),

  // Multiple distinct fields
  profile: route.post('/profile',
    fileUpload.fields([
      { name: 'avatar', maxCount: 1 },
      { name: 'cover', maxCount: 1 },
    ]),
    ({ req }) => {
      // req.files is a dictionary Record<string, UploadedFile[]>
      return { files: req.files }
    }
  ),
})
```

### C. Integrating Express/Connect Middleware (e.g. Multer)

If your enterprise project relies on existing Express middleware like **Multer** (for custom storage engines, S3 direct-to-cloud streams, or specialized filters), ExisJS provides the `fromExpress()` bridge:

```typescript filename="src/http/legacy/route.ts"
import { controller, route } from 'exisjs/router'
import { fromExpress } from 'exisjs/middleware'
import multer from 'multer'

const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 10 * 1024 * 1024 },
})

export default controller({
  upload: route.post('/', 
    fromExpress(upload.single('file')),
    ({ req }) => {
      // Access multer's req.file or req.body seamlessly
      const file = (req.raw as any).file || req.file
      return { success: true, originalname: file?.originalname }
    }
  )
})
```

### D. Manual `req.formData()` & Streaming Uploads

For manual control over incoming multipart streams without route middleware:

```typescript filename="src/http/upload/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  uploadAvatar: route.post('/avatar', {
    async handle({ req }) {
      // Parse on-demand
      const { fields, files } = await req.formData()
      const uploadedFile = files['profile_pic']
      
      if (uploadedFile) {
        // Save to disk safely with automated collision-free naming
        const savedPath = await uploadedFile.saveToDisk('./uploads/avatars')
        return { success: true, path: savedPath }
      }
      
      return { success: false, error: 'No file uploaded' }
    }
  })
})
```

## 4. Body Size Limits & HTTP 413

ExisJS comes pre-configured with a generous **10MB default body limit** (`10485760` bytes) across JSON, form-data, and raw payloads, preventing premature drops during photo or document uploads.

If a client sends a payload exceeding the configured threshold, ExisJS halts parsing immediately and responds with `413 Payload Too Large`:

```json
{
  "statusCode": 413,
  "error": "Payload Too Large",
  "message": "Request payload exceeded size limit of 10485760 bytes. Increase server.bodyLimit in exis.config.ts to allow larger payloads."
}
```

To configure custom limits globally across your app, update `exis.config.ts`:

```typescript filename="exis.config.ts"
export default {
  server: {
    // Set custom maximum payload limit in bytes (e.g. 50MB)
    bodyLimit: 50 * 1024 * 1024,
  }
}
```

## 5. Dynamic Request Timeouts

ExisJS ships with a **60-second default request timeout** in its `timeout()` middleware, offering ample headroom for slow network clients and third-party cloud operations (Cloudinary, AWS S3, OpenAI, Stripe).

### Dynamic In-Handler Control

Handlers can dynamically extend or cancel the active timeout on the fly using `req.setTimeout()` and `req.clearTimeout()`:

```typescript filename="src/http/ai/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  generateVideo: route.post('/', {
    async handle({ req }) {
      // 1. Extend timeout for heavy AI pass generation (e.g. 3 minutes)
      req.setTimeout(180000)

      try {
        const result = await longRunningAiTask()
        return { success: true, result }
      } finally {
        // 2. Clear timeout once work completes
        req.clearTimeout()
      }
    }
  })
})
```

## 6. HTTP Headers & Content Negotiation

```typescript
// Get a specific header (case-insensitive)
const authHeader = req.get('Authorization')
// or
const authHeader = req.header('authorization')

// Check the Content-Type
if (req.is('application/json')) { ... }

// Content Negotiation (returns the best match)
const format = req.accepts('html', 'json', 'text')
const language = req.acceptsLanguages('en', 'es', 'fr')
```

## 7. Network Information & IPv6 Normalization

ExisJS handles trust-proxies and dual-stack IP networks automatically. If you are behind Cloudflare, Nginx, or an AWS Load Balancer, simply set `trustProxy: true` in your `exis()` config, and these properties will automatically resolve the true client IP from `X-Forwarded-For`.

- **`req.ip`**: The client's IP address. Automatically normalizes IPv6-mapped IPv4 dual-stack addresses (e.g., `::ffff:192.168.1.50` $\to$ `192.168.1.50`) and converts IPv6 loopback `::1` $\to$ `127.0.0.1` for consistent rate limiting and geo-IP lookups.
- **`req.ips`**: An array of IPs if multiple proxies were traversed, each normalized cleanly.
- **`req.hostname`**: The resolved hostname (from `Host` or `X-Forwarded-Host`).
- **`req.protocol`**: Returns `'http'` or `'https'`.
- **`req.secure`**: A boolean (true if `req.protocol === 'https'`).

## 8. Request Cancellation & Abort Signals (`req.signal`)

ExisJS provides a first-class standard Web API `req.signal: AbortSignal` tied directly to the underlying HTTP connection lifecycle. 

When a client closes their browser tab, cancels a download, or aborts an HTTP request, `req.signal` immediately triggers an `abort` event. You can pass `req.signal` directly to ORMs, database drivers, and HTTP clients to cancel expensive in-flight operations and eliminate wasted server resources.

#### Example: Passing to Database Queries & Upstream Fetches

```typescript filename="src/http/reports/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  heavyReport: route.get('/', {
    async handle({ req }) {
      // 1. Pass req.signal to fetch() — if the client leaves, fetch aborts immediately
      const upstream = await fetch('https://api.external.com/data', {
        signal: req.signal
      })
      const payload = await upstream.json()

      // 2. Pass req.signal to your database queries (Prisma, Drizzle, pg, etc.)
      const results = await db.query(sql`SELECT * FROM heavy_analytics`, {
        signal: req.signal
      })

      return { payload, results }
    }
  })
})
```

## 9. Context & Metadata

As your request moves through ExisJS Middlewares, various properties are attached to `req` for your convenience:

- **`req.log`**: A request-scoped instance of the Pino logger (via `requestLogger`).
- **`req.requestId`**: The unique Trace ID (via `requestId`).
- **`req.user`**: The authenticated user payload (via `JWT` auth middleware).
- **`req.session`**: The stateful session object (via `session` middleware).
- **`req.fresh`**: Returns `true` if the client's cache is still valid (ETag match), meaning you can send a 304 response.

### Inline Context Typing (Per-Route)

If you don't want to create a globally typed router with `createRouter`, ExisJS natively types `req.user` as `any` by default so you never get annoying compiler errors (e.g. `req.user.userId` just works!). 

However, if you want **strict** type safety on a specific route without global configuration, you can pass your custom context directly to the route's 4th generic parameter:

```typescript
import { route } from "exisjs/router";

export default route.get<any, any, any, { user: { userId: string } }>("/", {
  async handle({ req }) {
    // Typed. No "as any" needed.
    const id = req.user.userId; 
  }
})
```

### Strongly-Typed Context & Native Destructuring (App-Wide)

To provide a better developer experience, ExisJS allows you to define a **custom typed context** for your application. This completely eliminates the need for global `.d.ts` augmentations and `as any` casts.

To do this, create a custom router factory (e.g., `src/http/router.ts`) and define the exact shape of your application's context (like the user object, workspace, tenant ID, etc).

```typescript filename="src/http/router.ts"
import { createRouter } from "exisjs/router";

// 1. Define everything your middlewares will attach to the request
interface AppContext {
  user: { id: string; role: string };
  workspace: string;
}

// 2. Export a custom typed route and controller
export const { route, controller } = createRouter<AppContext>();
```

Now, instead of importing from `exisjs/router`, import from your **local** router. Your handlers can natively destructure your custom properties.

```typescript filename="src/http/users/route.ts"
import { route, controller } from "../../router.ts";

export default controller({
  getProfile: route.get("/", {
    async handle({ user, workspace }) {
      // Strongly typed. 
      // No more `req.user`, no more `as any`.
      console.log(user.role, workspace);
    }
  })
});
```

<Warning>
**Important Middleware Rule:** In order for destructuring to work (e.g. `handle({ user })`), the `user` property MUST be populated **before** the handler executes. This means you must populate it inside a `middleware` instead of calling an inline function inside the handler.
</Warning>
