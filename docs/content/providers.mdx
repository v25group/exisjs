# Providers

Providers are a fundamental concept in ExisJS. Many of the basic classes may be treated as a provider: services, repositories, factories, helpers, and so on.

The main idea of a provider is that it can be injected as a dependency; this means objects can create various relationships with each other, and the function of "wiring up" instances of objects can largely be delegated to the ExisJS runtime system.

## Services

Let's start by creating a simple `UsersService`. This service will be responsible for data storage and retrieval, and is designed to be used by the `UsersController`. 

To mark a class as a provider that the ExisJS Inversion of Control (IoC) container can manage, we use the `@Injectable()` decorator.

```typescript filename="src/http/users/service.ts"
import { Injectable } from 'exisjs/decorators'

export interface User {
  id: string;
  email: string;
}

@Injectable({ scope: 'singleton' })
export class UsersService {
  private readonly users: User[] = []

  create(user: User) {
    this.users.push(user)
  }

  findAll(): User[] {
    return this.users
  }
}
```

Now that we have a service class to retrieve users, let's use it inside the `UsersController`. ExisJS provides a powerful `inject()` primitive that automatically resolves dependencies from the current context.

```typescript filename="src/http/users/route.ts"
import { Controller, Get, Post, Body } from 'exisjs/decorators'
import { inject } from 'exisjs/di'
import { UsersService, User } from './service'

@Controller('users')
export default class UsersController {
  
  // Clean, ergonomic dependency injection
  private usersService = inject(UsersService)

  @Post()
  async create(@Body() user: User) {
    this.usersService.create(user)
    return { success: true }
  }

  @Get()
  async findAll() {
    return this.usersService.findAll()
  }
}
```

<Info title="Note on Dependency Injection">
ExisJS utilizes a runtime container system. By default, ExisJS does not aggressively use `reflect-metadata` for automatic constructor injection (unlike NestJS) to maintain a minimal footprint. The `inject()` function is the primary and recommended way to resolve dependencies.
</Info>

### Extended: Manual Resolution
If you are operating completely outside of an ExisJS controller or route (for example, in a background worker, CRON job, or a raw script like a database seeder), you can manually resolve dependencies as an escape hatch via the app container:

```typescript filename="scripts/seed.ts"
import { getActiveApp } from 'exisjs/app'
import { UsersService } from './service'

const app = getActiveApp()
const usersService = app.container.resolve(UsersService)
```

## Service Lifecycle Hooks

ExisJS `@Injectable()` services can implement lifecycle interfaces. When the application starts up or shuts down gracefully, ExisJS automatically triggers these hooks on all managed singletons:

```typescript filename="src/http/database/service.ts"
import { Injectable, type OnInit, type OnDestroy } from 'exisjs/decorators'

@Injectable()
export class DatabaseService implements OnInit, OnDestroy {
  async onInit(): Promise<void> {
    // Invoked automatically during app startup (app.create / app.listen)
    await this.connectPool()
  }

  async onDestroy(): Promise<void> {
    // Invoked automatically during graceful termination (app.close / SIGINT / SIGTERM)
    await this.drainPool()
  }
}
```

## Service Method Enhancements

You can supercharge service methods with off-heap caching, automated transaction wrapping, and SLA performance profiling:

```typescript filename="src/http/users/service.ts"
import { Injectable, Cacheable, CacheEvict, Transactional, Profile } from 'exisjs/decorators'

@Injectable()
export class UsersService {
  constructor(private db: DatabaseService) {}

  // Caches return values off-heap in Rust LRU cache
  @Cacheable({ ttl: 300, key: (id: string) => `user:${id}` })
  @Profile({ thresholdMs: 100, warnSlow: true })
  async findById(id: string) {
    return this.db.query('SELECT * FROM users WHERE id = $1', [id])
  }

  // Runs in an atomic transaction; automatically rolls back on error
  @Transactional()
  @CacheEvict({ key: (id: string) => `user:${id}` })
  async updateUser(id: string, data: any) {
    return this.db.update('users', id, data)
  }
}
```

## Custom Providers

ExisJS's DI container is flexible. By default, when you register a class, ExisJS instantiates it for you. However, you often need more control. You can register standard classes, raw values, factories, or aliased classes natively using `app.provide()`.

### Functional Paradigm

```typescript filename="src/http/server.ts"
import exis from 'exisjs'
import { UsersService } from './users/service'

export default exis({
  async onStart(app) {
    // 1. Standard Class Provider
    app.provide(UsersService, UsersService)

    // 2. Value Provider
    app.provide('DATABASE_URL', {
      useValue: 'postgres://localhost:5432/mydb'
    })

    // 3. Factory Provider
    app.provide('LoggerService', {
      useFactory: () => {
        return { log: (msg: string) => console.log(`[Logger]: ${msg}`) }
      }
    })

    // 4. Aliased Class Provider
    app.provide('AuthService', {
      useClass: UsersService
    })
  }
})
```

### Class-Based (OOP) Paradigm

```typescript filename="src/http/server.ts"
import { Server } from 'exisjs/decorators'
import { UsersService } from './users/service'

@Server({
  providers: [
    // 1. Standard Class Provider
    UsersService,
    // 2. Value Provider
    ['DATABASE_URL', { useValue: 'postgres://localhost:5432/mydb' }],
    // 3. Factory Provider
    ['LoggerService', { useFactory: () => ({ log: (msg: string) => console.log(`[Logger]: ${msg}`) }) }],
    // 4. Aliased Class Provider
    ['AuthService', { useClass: UsersService }]
  ]
})
export default class RootServer {}
```

### Constructor Injection (`@Inject` and `@Optional`)

In addition to property-level `inject()`, ExisJS provides full OOP constructor parameter injection with `@Inject(token)` and `@Optional()`:

```typescript filename="src/http/users/route.ts"
import { Controller, Get, Param, Inject, Optional } from 'exisjs/decorators'
import { UsersService } from './service'

@Controller('/users')
export default class UsersController {
  constructor(
    private usersService: UsersService,
    @Inject('DATABASE_URL') private dbUrl: string,
    @Optional() @Inject('METRICS') private metrics?: any
  ) {}

  @Get('/:id')
  async getUser(@Param('id') id: string) {
    return this.usersService.findAll()
  }
}
```

## Injection Scopes

For people coming from different programming language backgrounds, it might be unexpected to learn that in ExisJS, almost everything is shared across incoming requests. We have a connection pool to the database, singleton services with global state, etc. This is because Node.js doesn't follow the request/response Multi-Threaded Stateless Model.

However, there are use-cases when request-based or transient lifetime is desired. ExisJS supports three provider scopes in the `@Injectable()` decorator and `app.provide()`:

- **Singleton (Default)**: A single instance of the provider is shared across the entire application.
- **Request**: A new instance of the provider is created exclusively for each incoming request, and garbage collected afterward.
- **Transient**: A brand-new instance is created every single time the dependency is requested/injected.

```typescript
@Injectable({ scope: 'transient' })
export class OperationContext {
  public readonly id = crypto.randomUUID()
}
```

> [!WARNING]
> **Request Scope Constraints**: A provider marked as `scope: 'request'` **must** be resolved within the lifecycle of an active HTTP request. If you try to `inject()` or resolve a request-scoped provider during application startup, inside a background queue worker, or from a cron job, the container will throw a runtime error.

## Database Providers & Lifecycle Interop (`exisjs/database`)

ExisJS provides first-party lifecycle management and transaction coordination for databases (PostgreSQL, SQLite, MySQL, MongoDB, Prisma, Drizzle, Mongoose).

### 1. Registering Database Lifecycle (`registerDatabase`)

Registering your database with `registerDatabase` ensures connections are automatically connected on boot and safely closed with zero leaked sockets when the server receives `SIGTERM` / `SIGINT`:

```typescript filename="src/http/server.ts"
import { exis } from 'exisjs'
import { registerDatabase } from 'exisjs/database'
import mongoose from 'mongoose'

export default exis({
  async onStart(app) {
    // Automatically handles startup and graceful shutdown
    registerDatabase(app, {
      name: 'mongodb',
      connect: async () => {
        await mongoose.connect(process.env.MONGODB_URI!)
      },
      disconnect: async () => {
        await mongoose.disconnect()
      },
      healthCheck: async () => {
        return mongoose.connection.readyState === 1
      },
    })
  }
})
```

### 2. Universal Transaction Runner (`withTransaction`)

`withTransaction` provides a duck-typed transaction runner that automatically coordinates transaction lifecycles, commits, aborts, and session cleanups across different ORMs:

```typescript filename="src/http/orders/service.ts"
import { withTransaction } from 'exisjs/database'
import mongoose from 'mongoose'
import { Order } from '@/models/Order'
import { Inventory } from '@/models/Inventory'

export async function placeOrder(customerId: string, items: { sku: string; qty: number }[]) {
  return withTransaction(mongoose, async (session) => {
    // Automatically attaches session to queries and commits/aborts on error
    const order = await Order.create([{ customerId, items }], { session })
    
    for (const item of items) {
      const updated = await Inventory.findOneAndUpdate(
        { sku: item.sku, stock: { $gte: item.qty } },
        { $inc: { stock: -item.qty } },
        { session, returnDocument: 'after' }
      )
      if (!updated) {
        throw new Error(`Insufficient stock for SKU: ${item.sku}`)
      }
    }

    return order[0]
  })
}
```

Works identically with Prisma (`prisma.$transaction`) and Drizzle (`db.transaction`).

### 3. Modern Mongoose 8/9 Interop & Connection Pooling

ExisJS exports helpers to prevent deprecation warnings in modern Mongoose:

```typescript filename="src/models/user.ts"
import { modernUpdateOptions, mongoPoolOptions } from 'exisjs/database'
import mongoose from 'mongoose'

// Cloud-hardened pool options (maxPoolSize, serverSelectionTimeoutMS, etc.)
export const poolConfig = mongoPoolOptions({ maxPoolSize: 50 })

// Automatically maps legacy { new: true } to { returnDocument: 'after' }
export async function updateUsername(id: string, name: string) {
  return User.findByIdAndUpdate(
    id,
    { $set: { name } },
    modernUpdateOptions({ returnDocument: 'after' })
  )
}
```
