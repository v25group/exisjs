# Installation & Setup

This guide provides step-by-step instructions for creating a new ExisJS application with the `create-exisjs` scaffolding tool or installing the framework manually into an existing TypeScript project.

---

## Prerequisites

Before starting, ensure your system satisfies the following requirements:

- **Node.js**: `v20.0.0` or higher
- **Package Manager**: `npm` (v10+), `pnpm` (v9+), `yarn` (v1.22+ or berry), or `bun` (v1.0+)
- **Operating System**: macOS, Linux, or Windows (x64 and ARM64 architectures supported)

Verify your Node.js version by running:

```bash
node -v
```

---

## Scaffolding a New Project

The quickest way to start a new ExisJS project is with the official `create-exisjs` scaffolding tool.

### Interactive Scaffolding

Run the creation command using your preferred package manager:

```bash
# npm
npm create exisjs@latest my-api

# pnpm
pnpm create exisjs my-api

# yarn
yarn create exisjs my-api

# bun
bun create exisjs my-api
```

The CLI prompts you with configuration options:

```text filename="Terminal"
? What is your project named? › my-api
? Would you like to use TypeScript? › Yes / No
? Would you like to use ESLint? › Yes / No
? Which routing paradigm do you prefer? › Functional (Default) / Class-Based (OOP)
? Would you like to customize the import alias (`@/*` by default)? › No / Yes
```

---

### Non-Interactive Command-Line Flags

For automated environments, Docker initialization, or CI/CD pipelines, you can pass command-line flags to skip interactive prompts:

```bash
npx create-exisjs@latest my-api --ts --functional --eslint --yes
```

#### Complete CLI Flag Reference

| Flag | Description | Default |
| :--- | :--- | :---: |
| `--ts`, `--typescript` | Configure project with TypeScript | `true` |
| `--js`, `--javascript` | Configure project with plain JavaScript | `false` |
| `--functional` | Configure project using functional paradigm (`controller()`, `route.*`) | `true` |
| `--oop` | Configure project using class-based decorator paradigm (`@Controller()`, `@Get()`) | `false` |
| `--eslint` | Generate ESLint flat config with TypeScript rules | `true` |
| `--no-eslint` | Skip ESLint setup | `false` |
| `--skip-install` | Scaffold directory tree and templates without installing dependencies | `false` |
| `--skip-git` | Skip automatic `git init` initialization | `false` |
| `--yes`, `-y` | Accept default configuration non-interactively | `false` |
| `--use-pnpm` | Force dependency installation via `pnpm` | Auto-detected |
| `--use-bun` | Force dependency installation via `bun` | Auto-detected |
| `--use-yarn` | Force dependency installation via `yarn` | Auto-detected |
| `--use-npm` | Force dependency installation via `npm` | Auto-detected |

## Generated Project Layout

Once the scaffolding finishes, your project contains the standard ExisJS directory layout:

```
my-api/
├── .agents/
│   └── rules/
│       └── AGENTS.md            # Architecture rules and agent guidelines
├── src/
│   ├── common/
│   │   └── guards/
│   │       └── auth.guard.ts    # Reusable route guards
│   ├── config/
│   │   └── env.ts               # Type-safe environment validation (tex.env)
│   ├── cron/
│   │   └── cleanup.ts           # Scheduled background tasks
│   ├── database/
│   │   └── db.ts                # Database lifecycle and connection
│   └── http/
│       ├── health/
│       │   └── route.ts         # Health check endpoint (/health)
│       ├── users/
│       │   ├── route.ts         # User routes (/users)
│       │   ├── schema.ts        # Input validation schemas (tex.*)
│       │   └── service.ts       # Service layer logic
│       ├── boundary.ts          # Root middleware, CORS & error boundary
│       ├── route.ts             # Root route handler (/)
│       └── server.ts            # Application lifecycle (onStart / onClose)
├── tests/
│   └── users.e2e-spec.ts        # End-to-end test suite
├── .env                         # Environment variables
├── .gitignore
├── .prettierrc
├── eslint.config.mjs            # ESLint configuration (when selected)
├── exis.config.ts               # Framework configuration
├── package.json
└── tsconfig.json
```

## Manual Installation

To install ExisJS into an existing repository without scaffolding:

### Step 1: Install Core Dependencies

```bash
npm install exisjs
npm install -D typescript @types/node prettier
```

### Step 2: Configure `tsconfig.json`

Create or update `tsconfig.json` to configure module resolution and metadata reflection:

```json filename="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "lib": ["esnext"],
    "allowJs": true,
    "skipLibCheck": true,
    "strict": true,
    "esModuleInterop": true,
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "module": "esnext",
    "moduleResolution": "bundler",
    "resolveJsonModule": true,
    "isolatedModules": true,
    "noEmit": true,
    "paths": {
      "@/*": ["./src/*"]
    },
    "types": ["node"]
  },
  "include": [
    "src/**/*.ts",
    "tests/**/*.ts",
    "*.config.ts",
    "*.ts"
  ],
  "exclude": ["node_modules", ".exis", "dist", "build"]
}
```

> [!NOTE]
> `experimentalDecorators` and `emitDecoratorMetadata` are required when using the class-based (OOP) paradigm (`@Controller()`, `@Injectable()`).

### Step 3: Create `exis.config.ts`

Create an `exis.config.ts` file in the project root:

```typescript filename="exis.config.ts"
import type { ExisConfig } from 'exisjs/config'

const config: ExisConfig = {
  port: Number(process.env.PORT) || 4000,
  host: '0.0.0.0',

  cors: {
    origin: process.env.CORS_ORIGIN || '*',
    credentials: true,
  },

  logger: {
    level: 'debug',
    pretty: process.env.NODE_ENV !== 'production',
  },

  helmet: { enabled: true },
  compression: true,
}

export default config
```

### Step 4: Configure NPM Scripts

Add the standard ExisJS CLI commands to `package.json`:

```json filename="package.json"
{
  "scripts": {
    "dev": "exisjs dev",
    "build": "exisjs build",
    "start": "exisjs start",
    "routes": "exisjs routes",
    "test": "exisjs test",
    "doctor": "exisjs doctor"
  }
}
```

## Verifying the Installation

### 1. Create a Health Check Endpoint

Create `src/http/health/route.ts`:

#### Option A: Functional Route

```typescript filename="src/http/health/route.ts"
import { controller, route } from 'exisjs/router'

export default controller({
  check: route.get('/', {
    summary: 'Service health check',
    handle: () => ({
      status: 'ok',
      timestamp: new Date().toISOString(),
    }),
  }),
})
```

#### Option B: Class-Based Route

```typescript filename="src/http/health/route.ts"
import { Controller, Get, ApiOperation } from 'exisjs/decorators'

@Controller()
export default class HealthController {
  @Get('/')
  @ApiOperation({ summary: 'Service health check' })
  check() {
    return {
      status: 'ok',
      timestamp: new Date().toISOString(),
    }
  }
}
```

### 2. Start the Development Server

Execute the `dev` script:

```bash
npm run dev
```

Output:

```text filename="Terminal"
[exis] starting development server (v0.7.12)...
EXIS ready in 125 ms

→ Local:   http://localhost:4000/
→ Docs:    http://localhost:4000/docs
→ Network: http://127.0.0.1:4000/
```

### 3. Verify the Endpoint

Send an HTTP GET request to verify the route:

```bash
curl http://localhost:4000/health
```

Expected JSON response:

```json
{
  "status": "ok",
  "timestamp": "2026-10-02T11:35:00.000Z"
}
```

Open `http://localhost:4000/docs` in your browser to inspect the interactive Swagger UI.
