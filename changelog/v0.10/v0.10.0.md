# ExisJS Release v0.10.0 (unreleased draft)

**Status:** In development on `main`. Not published.  
**Type:** Minor: settings that did nothing now work or fail at start-up; metrics endpoint  
**Affected Packages:** `exisjs`, `create-exisjs`, `@exisjs/fetch`

Fixes B1 to B7 from the 0.9.2 report (`docs/REPORT.md`), plus B9, found while verifying the Docker guide. B8 (moving the build tooling out of production installs) is planned separately.

---

## Breaking Changes

0.10.0 follows the project rule that a setting which is accepted but does nothing is worse than no setting. Each change below makes a server that seemed fine fail at start-up, with a message naming the option.

1. **`queue` is checked at start-up (B2).**
   - `queue.driver` must be `'memory'`. `'redis'` and any other value stop the start. They never did anything: there is no Redis queue.
   - Unknown keys stop the start. The `03-all-features` example had `enableWorkers: true`, which nothing ever read; remove it if you copied that block.
   - `queue` now applies backpressure (see Added). With `queue: { driver: 'memory' }` alone, the defaults apply: 1000 requests at once, 500 waiting, 10 s wait.

   **Migrate:** delete `queue.driver: 'redis'` and unknown keys, or delete the `queue` block if you don't want a limit.
2. **`tex.object(shape, options)` rejects unknown options (B4).** In plain JavaScript a misspelled option such as `{ optinal: true }` used to be ignored. It now throws when the schema is defined.
3. **Outside development, a route file that cannot load stops the start (B9).**
   - Before, it was logged and skipped: the server started without that part of its API and reported healthy.
   - The usual cause is a missing environment value read by `tex.env` while the route file loads.

   **Migrate:** provide the variable, or fix the file named in the message. Development (`exisjs dev`) is unchanged: such a route answers `500` with the error.

## Added

- **Prometheus metrics (B1).** `metrics: { enabled: true }` now serves `GET /metrics`. Before, the setting was accepted and no route existed.
  - Request counts and duration histograms are labelled by route pattern (`/users/:id`), never the raw URL.
  - Also reported: requests in flight, memory and event-loop lag.
  - In cluster mode, a scrape that reaches any worker reports the totals of every worker.
- **`queue` limits concurrent requests (B2).** `queue: { maxConcurrent, maxQueue, timeoutMs }` caps requests handled at once. Extra requests wait, then get `503`.
- **`tex.object()` takes `optional`, `nullable` and `nullish` (B4),** like the field builders, with matching types.
- **Docs: "Deploying with Docker" (B7).** It covers:
  - a tested multi-stage Dockerfile and `.dockerignore`;
  - why the build needs `--skip-env-check`, and that `tex.env` still refuses to start without the secrets;
  - running `node_modules/.bin/exisjs start` instead of `npm start`;
  - health checks and migrations.

## Fixed

- **`ValidatorError` was not exported from `exisjs/validator` (B3).** Neither were `TexBuilder`, `TexType`, the option types, or `SafeParseResult`, although the API reference listed them. Use `err instanceof ValidatorError`.
- **Ctrl+C in `exisjs dev` printed `Failed to start process: write EPIPE` (B5).** On Windows the server process often exits first; telling it to stop then failed, and the error was printed as a start failure. A closed channel during shutdown is now expected, and real errors after start are reported as `Server process error`.
- **`exisjs dev` did not reload when the project sat inside a folder such as `Temp`, `data`, `build` or `public` (B6).** The watcher matched its ignore rules against the full path, so every file of such a project was ignored, `.env` included. The rules now apply only inside the project. `.env` files are also watched when `watch.paths` is set.
- **Backpressure leaked a slot for every streamed or aborted response.** It counted a request as finished only through `res.end()`, so a server under the limit eventually queued or rejected everything. It now counts the connection closing. A client that gives up while waiting also frees its place in the queue.
- **Production startup hid a broken routes manifest.** If the manifest could not be imported, a warning was logged and the server fell back to scanning the source folders; it now stops (B9).

## Upgrade Notes

- Check `exis.config.ts` for a `queue` block. Keep it only if you want the limit, and remove `driver: 'redis'` and unknown keys.
- If a deployment starts without all its environment variables, it now exits with code 1 instead of serving part of the API. Check the platform's environment settings before upgrading.
