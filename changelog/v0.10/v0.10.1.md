# ExisJS Release v0.10.1

**Status:** Unreleased (draft)  
**Type:** Patch: one critical and two high-severity bugs, security fixes behind proxies, test runner fixes  
**Affected Packages:** `exisjs`, `@exisjs/cli`, `create-exisjs`

**Upgrade if you use `compression: true`** (the project template's default). In 0.10.0, any response large enough to be compressed reached browsers as `204 No Content` with no body.

---

## Behaviour changes

Each is a fix, but a running app can notice it. Check the ones that apply before upgrading.

1. **`trustProxy: true` no longer reads `True-Client-IP`, `X-Real-IP` or `X-Client-IP`.** Any client can send these, so it could choose its own `req.ip` and get a fresh rate-limit bucket on every request. `true` now reads `CF-Connecting-IP`, then `X-Forwarded-For`.
   **Migrate:** behind nginx that sets only `X-Real-IP`, use `trustProxy: { header: 'x-real-ip' }`. Behind Cloudflare, use the new `trustProxy: 'cloudflare'`.
2. **Access is checked before input is validated.** An anonymous request with a bad body to a protected route now gets `401` (a signed-in user without the permission gets `403`), not a `400` that lists the expected fields.
3. **`exisjs test` fails a test file whose process doesn't exit.** Five seconds after a file's last test, if something is still open (a database client, a server, a timer), the file fails with a message naming it. Before, the whole run hung with no output.
   **Migrate:** close it in an `after()` hook, or run `exisjs test --force-exit`.
4. **The default `healthcheck.drainMs` in production is 2 seconds** (was 5). Drain plus up to 5 seconds for requests now fits inside Docker's default 10-second stop period. Set `drainMs` to keep the old value.
5. **`hpp()` leaves JSON bodies alone.** It used to replace every array in a JSON body with its last element.

## Fixed

- **Compressed responses were sent as `204` with no body** (`compression: true`). The router saw the response as unsent while zlib was still working. The test client now decodes `gzip`, `br` and `deflate`, so a test that sends `Accept-Encoding` sees the body.
- **`hpp()`** turned `{ "ids": ["a", "b"] }` into `{ "ids": "b" }`, so strict schemas answered "Must be an array" and loose ones lost data. It now only flattens repeated query keys and form fields, with a `whitelist` option for keys that may repeat (`?tags=a&tags=b`).
- **Boundary files loaded a second copy of every module they import under `NODE_ENV=test`.** Each database client and module-level cache existed twice, and the test process never exited. Boundaries and routes now share one real `import()`, and a file that fails to load reports its own error instead of a `require()` fallback hiding it.
- **`exisjs test` printed nothing while it hung**, and the reporter counted top-level `it()` tests (outside a `describe`) only sometimes. Each file now prints when it finishes, with `PASS` or `FAIL` from its real result.
- **`csrf()` behind a reverse proxy** compared the browser's `Origin` with the upstream `Host`, so every state-changing request failed with `403 CSRF_FAILED`. With `trustProxy` set it now uses `X-Forwarded-Host`. Outside production, a mismatch puts the expected host and the received origin in `details`.
- **`mongoSanitize()`** dropped every dotted key without a way to keep them, which broke webhook handshakes such as Meta's `hub.mode`. It also tried to parse every body as JSON.
- **A `/_ready` `503` during shutdown was logged as an error** on every deploy. It is intended, so it now logs at `info`. A `503` because a database is down still logs as an error.
- **`create-exisjs` templates:** routes were open unless remembered, and the example guard allowed any `Authorization` header.
- **Docs:** the Dockerfile's `HEALTHCHECK` used port 3000 and the template's `/health` route; the testing page showed the wrong validation error shape and a `--coverage` flag that doesn't exist.

## Added

- **`trustProxy: 'cloudflare'`** trusts `CF-Connecting-IP` only when the request came from a Cloudflare address, directly or through a local proxy (Traefik, nginx) whose last hop is Cloudflare. **`trustProxy: { header }`** reads one header your own proxy sets.
- **A warning when requests come through a proxy and `trustProxy` is off** (production, once): every client then shares the proxy's address and one rate-limit bucket.
- **`req.host`**: the host with its port, from `X-Forwarded-Host` behind a trusted proxy. **`req.csrfToken`** is now part of the request type.
- **`csrf({ allowedOrigins })`** for an API served from another host than the site.
- **`mongoSanitize({ allowDots, exclude })`**.
- **`logger.quietPaths`**: more paths whose successful requests log at `debug`, like the health probes.
- **Lockouts keyed on a body field:** `consume(store, key, { max, windowMs })` and `assertNotLimited(store, key, { max, windowMs })` throw the standard `429 RATE_LIMIT_EXCEEDED`. `RateLimitStore` gains optional `get()` and `reset()`, which the memory store implements. The security docs include a MongoDB store.
- **`exisjs test --force-exit`**, and `EXIS_TEST_EXIT_GRACE_MS` to change the five seconds.
- **`create-exisjs`**: new projects deny by default (`authorization: { defaultPolicy: 'authenticated' }`), with the root, health and example users routes marked public, and turn on the `/_health` and `/_ready` probes. The example guard refuses until it is implemented.
- **Docs:** "Going to production" (Dokploy, environment quoting, Cloudflare, an authentication checklist, seed scripts, health), liveness versus readiness, when a longer drain helps, and what happens when a database can't connect at start.

## Upgrade

```sh
npm install exisjs@0.10.1
npm install -D @exisjs/cli@0.10.1
```

Then check the behaviour changes above, especially `trustProxy: true` behind nginx and test files that leave a connection open.
