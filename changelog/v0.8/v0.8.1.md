# ExisJS Release v0.8.1

**Release Date:** 2026-10-12  
**Type:** Patch: Security Fixes & Deployment Build Fix  
**Affected Packages:** `exisjs`, `create-exisjs`, `@exisjs/fetch` (all aligned to `0.8.1`)

---

## Highlights

- **Two security fixes** in `ipFilter` and `serveStatic`. Upgrade if you use either.
- **Deploys no longer fail on hosts that skip `devDependencies`** (Render, Heroku and others).

---

## ⚠️ Behavior Change: `ipFilter` behind a proxy

`ipFilter` now checks `req.ip` and nothing else. If your app runs behind a proxy or load balancer and you use `ipFilter` (or `@IpFilter`), set `trustProxy` in `exis.config.ts`, otherwise `req.ip` is the proxy's address:

```typescript filename="exis.config.ts"
export default {
  trustProxy: 1, // number of proxies in front of the app
}
```

Without it, an allow-list will reject every request (it sees the proxy address) and a deny-list will not match clients. The `trustProxy` option of `ipFilter` itself is deprecated and ignored.

---

## Security

- **`ipFilter` allow-lists and deny-lists could be bypassed.** The middleware read the first value of `X-Forwarded-For` by default, a header any client can set. Sending `X-Forwarded-For: 10.0.0.1` was enough to pass `ipFilter({ allow: ['10.0.0.0/8'] })`, and any value was enough to escape a deny-list. It now uses `req.ip`, which only honors forwarding headers from proxies the app is configured to trust.
- **`serveStatic` could serve files from a sibling directory.** The root check compared path prefixes without a separator, so with a root of `public`, a request for `/../public-private/file` was served from a neighbouring directory whose name starts with `public`. Directories that do not share the root's name prefix were never reachable. The check now requires the path to be inside the root.

## Fixed

- **`exisjs build` failed on hosts that install without `devDependencies`.** With `NODE_ENV=production`, `npm install` leaves out `@types/node` and other `@types/*` packages, and the build's type-check reported dozens of errors such as `Cannot find name 'process'` on correct code. When `@types/*` packages listed in `devDependencies` are not installed, the build now skips the type-check with a warning and compiles as usual. To keep the type-check on the host, install with `npm install --include=dev`.

## Changed

- `dbSanitize()` reuses `mongoSanitize()` instead of carrying a copy of its code. No behavior change.

## Tooling

- Updated the `proxy-addr` development dependency (advisory GHSA-jqcg-44mw-7w3h). It is used only by the benchmark suite and was never part of the published packages.

## Upgrade Guide

```bash
npm install exisjs@0.8.1
```

No code changes are needed unless you use `ipFilter` behind a proxy; see the behavior change above.
